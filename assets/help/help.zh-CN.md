# Audastra 使用帮助

## 开始

- 打开地图：顶栏“文件 → 打开”，或把 .w3x / .w3m 拖进窗口。
- 保存：写回当前打开的地图。保存前自动备份，备份目录和保留份数在“设置 → 地图测试”里改。
- 另存为：写到你选的新路径。
- 保存时，如果这次改动不影响游戏脚本（例如只改了物编、导入文件），会沿用地图原来的 war3map.j；触发器、单位摆放或可玩区域等影响游戏初始化的修改会重建脚本并编译检查。重建脚本与原脚本的函数签名不同时，错误列表会列出来。
- 新建地图：洛丹伦夏季平地，64 × 64（可玩 52 × 52），1 名人类玩家，触发器为空，不带对战基地和胜负条件。
- 测试地图：F9。普通地图直接启动所选魔兽，不需要额外的测试程序。

## 错误列表

窗口底部的错误列表和代码页下方的检查结果都按级别分类，和 Visual Studio 一样：

- 点“错误 / 警告 / 消息”按钮可以单独显示或隐藏这一类，按钮上是数量。
- 双击一行跳到出错位置。
- “消息”里放的是补充情况，例如只做了语法检查、来源清单不完整、编码不是 UTF-8、列表只显示了前 512 项。
- 触发器改动暂时不能写回地图时，会在错误列表里出一条“警告”，说明原因。

## 触发器

- 双击或按 Enter 编辑参数；F2 打开完整参数对话框。
- 数组变量需要下标，只能在参数对话框（F2）里选。
- 参数选择按“变量 → 函数 → 固定值”分页，Ctrl+Tab 换页，Esc 关闭，右下角可以拖动调整大小。结果太多时只列前 400 个，输入名称或 ID 缩小范围。
- 已禁用的触发器不生成代码；“初始关闭”的触发器会生成 DisableTrigger。
- 注释条目和触发器注释都不生成代码。
- 自定义代码触发器暂时不能直接改名或复制，因为要同步 InitTrig 和代码里的生成符号。

### 自定义代码

- 修改后是“未应用”草稿；保存地图或切换触发器前会自动提交，提交失败时正文保留。
- 已应用的代码在保存地图时编译检查。
- 含特殊空白字符（无法无损编辑）的正文只读，原字节保留。
- 地图来源变了时草稿保留，可以复制正文或放弃草稿后重新载入。

### 查找与替换

- 只查找和替换传统触发器（T）里的参数、函数、变量和物体引用，不改 JASS / Lua 正文。
- 替换目标只能从已有的变量声明或物体目录里选，不会按四字码前缀猜类型。
- 先勾选、再预览；全部通过类型校验才能应用，一次撤销还原整批。预览有任何不能替换的项，整批都不应用，不会悄悄跳过。

### 函数库

- 启用和顺序保存在本机设置里，不修改数据目录的 config。
- 后加载的包覆盖同名定义。
- 地图用到但本机关闭的包，可以只对这张地图启用。
- 编辑器自带 AudastraUI 函数库（界面触发器用）：在函数库窗口点“安装 AudastraUI”，写进数据目录的 ui\AudastraUI 并启用，不修改 config。用 YDWE 打开同一张图前，要自己把 AudastraUI 加进 config。

## Lua 脚本

- 地图里的 .lua 文件随地图保存；保存前检查 Lua 5.3 语法，支持 YDWE 的 |xxxx| 四字码写法。
- 在文件里用 `require "jass.common"` 调用 common.j 的 native。blizzard.j 里的 BJ 函数在 Lua 里不能直接用。
- 游戏开始时加载：在地图初始化触发器里加一个“自定义代码”动作：

  ```
  call Cheat("exec-lua: \"main\"")
  ```

  它会加载地图根目录的 main.lua。子目录用点号，例如 lua\main.lua 写成 `lua.main`。
- 完整示例：菜单“新建 Lua 教程地图”，教程里每个文件都有注释。
- 测试地图时修改并应用 Lua 文件，再点工具栏的“热重载”，新代码会送进正在运行的游戏。
- 不是 UTF-8 编码、或含特殊空白字符的文件只读查看，原字节保留。
- 删除的文件可以用“撤销资源修改”恢复。

### 代码补全

- 输入名字时自动弹出候选；JASS 输入两个字符后弹出。Ctrl+空格随时打开。
- 上下键选择，Enter 或 Tab 接受，Esc 关闭。输入 ( . : 时会先接受选中的候选。
- 候选按开头匹配排在前面，也支持只输入每个单词的首字母，例如 cu 找到 CreateUnit。
- 右侧显示选中项的参数和说明；说明来自游戏 common.j 里声明上方的注释。
- 输入 `jass.` 之后列出 common.j 的 native 和常量；`require "` 之后列出地图里的 Lua 模块，`require` 拿到的模块可以继续点出它的函数和字段。
- 函数调用括号里显示参数提示，当前参数加粗；JASS 的提示来自 common.j、blizzard.j、函数库和地图脚本里的声明。
- 候选里也有关键字。JASS 在起新名字的位置（如 `local unit 名字`、`function 名字`）不自动弹出。
- 鼠标停在名字上显示类型和说明。能推断出的局部变量会显示类型，例如 `local u = jass.CreateUnit(...)` 的 u 是 unit。
- 错误列表会提示 common.j 里不存在的 native、参数个数不对、参数类型明显不对（例如把小数传给 integer），以及 require 了地图里没有的模块。推断不出类型的值不检查。
- 接口来自“设置”里所选游戏目录的 common.j；没有设置游戏目录时只有 Lua 标准库的补全。
- Lua 地图的触发器自定义代码也一样；头部和其它代码块里定义的全局函数、变量在当前代码块里也能补全。

## 世界

### 选择与视角

- 单击选择，拖动框选；Shift 加选，Ctrl 减选；双击目录里的对象把视角对准它。
- Ctrl+右键或 Alt+左键旋转视角；中键或右键平移；滚轮缩放。
- 目录里的眼睛和锁只改变编辑器里的显示和锁定，不影响地图和游戏。
- 不同类别一起选中时，共同属性只读。

### 摆放与编辑

- 从资源浏览器选物体后左键连续放置，或直接拖进视口；右键或 Esc 结束。
- Ctrl 按 32 吸附；高度跟随地形。
- 选中摆放后：拖动移动，Alt+拖动旋转单个，Ctrl+C 复制，Delete 删除。多选时输入的数值应用到全部所选，可以一起撤销。
- 整组粘贴：移动鼠标定位，左键放下，右键或 Esc 结束。
- 区域：拖动内部移动，拖动角调整大小（按 32 对齐）。镜头：拖动目标点移动。
- 在场景目录的“新建”菜单中创建区域或镜头；选中后可编辑完整属性、制作副本或删除。“地图实例”页提供相同操作，修改可以撤销。
- 区域和镜头常被触发器按名字引用，更名或删除前会检查引用。已有引用须先修改；自定义代码或未完整读取的触发器造成覆盖缺口时，会拒绝操作并列出原因。

### 地形

- 左键涂刷，[ 和 ] 调整笔刷尺寸，Esc 取消本笔。
- 附加通行限制：每格 32 单位，只追加限制或撤回本工程新增的限制，原图限制保留；橙框标记新增的格子。
- 水面：可以调整已有水面的高度，也可以用浅水、深水笔刷生成水面；新水面使用实际游戏资源中的水位规则。
- 悬崖：按一级升降或保持层级，使用源图已有的悬崖材质槽位；只换材质时保留高度、层级和变体。
- 坡道：可以保存含已有干地、湿地坡道的地图，仍需完整核对通行。“含水直坡”按每次点击创建、移除一级三点直坡，支持干地和含水形态；“拐角坡道”处理一级九点外角。多级台阶和相交新坡道暂不支持。
- 边界：橙色十字标记边界顶点，只设置或清除边界标志，保留地图外缘。
- 可玩区域：读取当前范围后调整西、南、东、北四条地格边界；东、北边界不包含在范围内。保持地图尺寸和对象坐标不变，可以撤销、重做；扩大或裁剪地图尺寸暂不支持。
- 地形修改可以保存工程，也可以通过“保存地图”或“另存为”写入地图。高度、荒芜、地面和悬崖材质、水面、普通悬崖、受支持的坡道、边界、可玩区域和附加通行限制均使用同一保存检查；缺少实际规则或无法解释原通行时会拒绝保存，并保留当前编辑。
- 经典格式的单位、建筑和物品摆放修改可与地形同次保存，脚本和地图标记使用最终摆放。开始位置的联动设置、装饰物的移动或增删，以及额外混合字段仍受各自限制，详细范围见《地形保存》。
- 普通保存保留原静态阴影，另用“计算阴影并保存”显式重算；超出当前计算范围时会拒绝该次计算。地图标记按最终地形和实际对象重新生成，小地图在支持范围内自动重建，生成能力或预算不足时保留原内容并提示原因。
- 保存前会核对实际地图成员和游戏资源，保存后独立回读；来源已改变、读取失败或后续阶段试图替换已冻结结果时，会拒绝保存。回读通过后仍请在地图副本上分别用原版编辑器重开、进游戏核对通行、外观和触发器。

### 模型诊断

- “按模型列出诊断”里双击一行定位到第一个受影响的摆放；数量是不同摆放的数量。

## 地图设置

- 支持经典版 W3I v25 地图设置的编辑；其他版本只读，原字节保留。
- 未识别的选项位和尾部数据原样保留。
- 科技与随机表目前只读。

## 物编

- 原版数据只读；修改原版对象时会创建地图字段覆盖。
- 批量修改：选择同类地图对象，再输入要一起设置的字段值。
- 声音类字段保存的是声音标签或组名，不接受文件路径，请在“选择”里选已有标签。

## 物体管理

- 引用统计只包含工程数据里的直接引用；自定义脚本文本和动态拼接不在其中，不能作为可以安全删除的依据。

## 战役

- 章节、菜单和共享数据分别编辑；保存战役写入 .w3n。
- “共享数据”和“资源”页的修改写入当前战役，不写入章节地图。

## 界面

- 界面工作区显示游戏自带界面、地图脚本创建的界面，以及地图自己的界面描述（AudastraUI\<编号>.json）。
- 编写：“新建界面”建一份描述，可选从“读条条”或“团队框架”起步（框架、数值、状态已连好）；选中描述或其中的框架，用“添加”放容器、背景、文字、进度条、按钮或模板（模板可按名字搜索）。画布上拖动框架移动它。
- 右侧“编辑”一组改所选框架：对齐点、目标、对齐方式和模板从列表选，颜色写 #AARRGGBB。在属性上右键可添加或删除锚点。
- 重复：填写次数后框架按间距排成一组；取值写成 编号[] 时，每个实例取数组里自己的那一格。清空次数即不重复。
- 贴图也可写取值，如 {icon[]}，按数值换图。显示绑定到文字数值时，文字非空才显示。
- 选中一个界面描述，点“生成触发器”：生成框架、数值和状态的全局变量，以及创建、更新、各状态和回到基础状态的触发器，放进触发器编辑器的 AudastraUI 类别。需要先装好并启用 AudastraUI 函数库。
- 再次生成会整体替换这些触发器；一次撤销还原。同时放入 AudastraUI\AudastraUI.toc 和 AudastraUI.fdf 两个模板文件。
- 触发器名末尾的英文部分（如 cast_Update）不要删，它让脚本里的触发器名不重复。
- 地图里改了数值变量后运行“更新”触发器刷新界面；切换状态运行对应的状态触发器。
- 锚在游戏代码区域（小地图、技能栏等）的框架暂时不能生成，会全部列出并整体拒绝。
- 界面要靠游戏里的 Audastra 运行库显示，目前只支持经典 1.27a。运行库在地图开始后要过一会儿才接通，所以“创建”触发器每 0.2 秒看一次“AudastraUI 界面库可用”，可用后建好界面并关闭自己；30 秒内仍不可用就停下，地图照常运行，只是界面不出现。界面建好前，“更新”和各状态触发器直接返回。
- 编辑器保存地图时还不会带上运行库；没有运行库时界面不显示，地图其他逻辑不受影响。

### 读条系统

- 界面工作区点“读条系统”生成一组触发器到“读条系统”类别，需要 YDWE 函数库。
- 在“读条 登记 Cast_Register”里每个技能写一组：技能、读条秒数、引导秒数、跳间隔（0 为不跳）、效果触发器。秒数要和物编的施法时间、持续时间一致。
- 效果触发器在三个时机运行：读条或引导完成（阶段 1）、引导每跳（阶段 2）、打断（阶段 3，含施法者死亡）。在效果触发器里用“获取逆天局部变量”取：施法单位、目标单位、目标X、目标Y、技能、等级、阶段、跳数。
- 读条能否移动、什么算打断由物编和游戏决定，系统只计时和运行效果触发器。
- 可以绑定一份界面描述作读条条：选“显示”（布尔）和“进度”（实数）数值，技能名、剩余秒数、引导状态、打断状态可选。只刷新本机玩家自己的读条。绑定前先给这份界面生成触发器。选“新建读条条”会按模板建一份界面、生成它的触发器并自动绑定。
- 再次生成会替换系统触发器，“登记”触发器保留不动。

### 团队框架

- 界面工作区点“团队框架”生成一组触发器到“团队框架”类别。绑定一份已生成触发器的界面描述，或选“新建团队框架”按模板建一份并自动绑定。
- 绑定的数值都是数组、格数相同：显示（布尔，必选，格数即队伍上限）、生命与法力（实数，0 到 1）、名字（字符串）、死亡与过远（布尔）。点选绑定一个点击事件，它的框架要在重复次数等于格数的重复框架里。
- 勾选“自动加入玩家英雄”时，开局已在地图上和之后进入地图的玩家英雄自动加入（不含幻象、电脑玩家）。自己加入或移出：把单位设给变量 AUP_Member，再运行“团队 加入 Party_Join”或“团队 移出 Party_Leave”。单位被移除后自动移出，后面的格子前移。
- 每 0.1 秒刷新一次并运行界面的“更新”触发器。过远按本机玩家在名单里的第一个队员量距离。鼠标经过格子时格子发亮；点格子只改本机的选择，选择由游戏同步。
- 增减益：勾选“增减益图标”数值（模板为增减益 1–4），在“增减益”里按顺序选要显示的增减益，图标取自物编。每格按这个顺序显示队员身上有的增减益。
- 增减益写进“团队 登记 Party_Register”，以后在触发器编辑器里改；再次生成时保留它，其余触发器整体替换。
- 过远与点选需要 YDWE 函数库。

## 设置

### 地图测试

- 扩展运行时目录：JAPI 地图留空时只读使用本机 YDWE 的运行库，不需要启动 YDWE；也可以填写包含六个 DLL 的独立目录。这些运行库由你本机安装提供，不随编辑器分发。
- SLK 优化由编辑器自己完成，只作用于测试副本，源地图不变。
- 备份：保存地图前自动备份；不同地图分别保留指定份数，0 表示不限。“检查旧版目录”只读核对旧版 backups 目录，不搬移或修改文件。

### 自动恢复

- 恢复工程（.forge）保存编辑状态，不会写回原地图，也不会把编辑标记为已保存。
- 异常退出后用“恢复编辑…”打开恢复工程。多个编辑窗口的恢复工程需要分别选择，启动时只提示最近一次。

### 特效显示

- 平衡：按画面耗时自动调整特效数量。省电：减少数量和刷新频率。完整：取消数量软限制，但仍遵守资源和内存限制。
- 世界视图状态栏会提示因预算省略的特效，点击可临时显示全部，切换地图后恢复所选设置。

### 助手

- 设置保存在当前用户目录；密钥只在保存设置时加密写入，取消不会写入。
- 地图逻辑默认写成可编辑的触发器（T）；写代码和执行外部命令由任务和权限共同控制。
- 关闭“修改”和“保存”后仍可查询。
- 助手可以列出、读取和整体改写地图里的 Lua 文件；改写进入撤销栈，替换已有文件要带上读取时的版本，文件期间被改过会拒绝。
- 助手可以把本机文件导入地图（模型、贴图、声音等），进入撤销栈，保存地图时写入；地图里已有同路径文件时要明确要求替换。
- 助手启动测试与工具栏“测试”相同，属于外部操作；游戏运行中可用热重载工具把已应用的 Lua 送进游戏。
- 关闭的工具从列表移除并拒绝执行；改了开关后，外部客户端需要刷新工具列表。
- 导入设置会先放进设置页，点“保存设置”才生效。

## 其他

- 命令面板：↑ ↓ 选择，Enter 执行，输入 > 只搜命令，Esc 关闭。
- 全局搜索：Ctrl+Shift+F，可搜名称、ID 或触发器参数。
- 浮动窗口：拖动标题栏到主窗口顶栏或右边缘可以停靠。
- 体积分析：数字是成员的未压缩字节，不是 w3x / w3m 文件在磁盘上的大小；没有应用的草稿不计入。
