# 地图测试与备份

1. 启动包根目录的 `Audastra.exe`，打开地图，在常规设置中选择 Warcraft III 安装目录。
2. 普通经典地图不需配置其他测试程序。测试使用这里选定的游戏目录，不读取旧 YDWE 配置或注册表中的另一条游戏路径。
3. 点击工具栏“测试”或按 F9。未保存修改会写入独立测试副本，原图、未保存标记和撤销记录保留。触发器或影响地图初始化的改动必须先成功重建脚本；编译未通过时会停止测试并显示原因。
4. 退出上一轮游戏后再测试。同一游戏安装同时只允许一场测试。关闭编辑器不会强行结束你的游戏。

测试会显示复制副本、冻结文件身份、读取脚本、检查调用、检查运行库和启动等实际阶段。保存后最终 JASS 的历史 UTF-8/GBK 注释、字符串及原字节物体 ID 按保存链同样的规则检查；测试不会要求再次将整篇脚本转换成一种编码，也不会为读脚本而解码地图的全部模型、贴图和音频。

使用扩展 JAPI 或旧版 Lua 引擎的地图，运行时目录留空时自动使用触发器数据设置中的本机 YDWE 安装：读取 `bin` 中的 `ydbase.dll`、`lua53.dll`、`ydwar3.dll`，以及 `plugin/warcraft3` 中的 `yd_loader.dll`、`yd_jass_api.dll`、`yd_lua_engine.dll`。也可在“设置 → 地图测试与备份”显式选择兼容的平铺运行库目录，显式选择优先。Audastra 自己负责加载，不启动 YDWE；GPLv3 库只读用户安装，不复制或随包分发。需要同一来源、经典 x86 / Lua 5.3 档案及可解析的 x86 VC 运行库，缺失或版本不兼容会给出路径与原因。普通地图不用配置运行库。

本版本在启动前拒绝原生 Lua 地图测试，目前仅接入经典客户端的 JASS 地图。六个旧插件不能使经典客户端自动兼容原生 Lua 格式；更换客户端也还需要后续适配。地图自身使用的其他插件、数据与 DLL 仍需与地图配套。

扩展运行时当前验证了静态文件检查及原创假程序的加载、初始化协议，尚未验证真实 JAPI 地图进图与 API 行为。六 DLL 不保证旧 Lua 模块全部可用：例如懒加载 `jass.slk` 还依赖原宿主的数据、语言与脚本布局。

“测试时启用 SLK 优化”默认关闭。优化由编辑器自己完成，只读取所选游戏目录的原版物编表，不需要 YDWE、Lua 或其他工具。开启后只转换测试副本：自定义物体写成物编表的行和说明文本，写不进表的修改留在物编文件里由游戏叠加读取；写出前逐字段核对每个转换物体的数值不变，核对不通过就停止测试。转换摘要和保留原因显示在问题面板。含 LNI 物编（`table` 目录）的地图不支持优化。请先关闭 SLK 验证地图可以进入，再开启比较实际加载时间和地图内容。

备份目录默认是本包目录下的 `backups`，可在同一设置页选择其他磁盘目录。保留数量按每张源地图计算，默认 10 份，0 表示不限数量。原地保存前创建备份；目录不可写时会中止保存。用户放入的其他文件和已修改备份不会被自动清理。

临时测试工作区在本包的 `test-maps` 中，游戏使用的短路径副本在所选安装的 `Maps/Audastra` 中。确认本轮游戏全部退出且原进程身份完整后，后台清理本轮已核验文件。内容变化或未知新增文件会保留并显示诊断。快速退出导致身份证据缺失时保留副本，确认 Job 已无活动进程后允许重新测试。应用提前退出时，未完成清理的测试目录可能保留。

扩展启动的终态报告保留在 `bin/test-receipts` 中。它区分模块加载、初始化和进程退出；初始化成功不代表地图已经进入游戏。本候选只经过静态检查、离线 SLK 与原创无窗口进程回归，真实地图进图仍由作者主动验收。
