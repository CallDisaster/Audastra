# 分发与验收契约

## 四层职责

| 层 | 保存什么 | 何时使用 |
|---|---|---|
| 类型目录 | 实际单位类型、初始化、事件角色、有序业务回调、清理规则 | 登记/类型改变时找到该实例需要的业务 |
| 实例订阅 | 单位身份与代次、活动订阅 token、初始化状态、生命周期归属 | 中央事件按相关实例定位少量回调 |
| 中央事件源 | 经目标版本证明的原生或插件入口、事件角色、源身份 | 每个事件只进入必要的共享源 |
| 清理 | 死亡业务、逻辑注销、底层资源回收、异步资源归属 | 死亡、移除、替换、复活及关闭时 |

类型目录是模板，不能因一个实例死亡删除整类业务。中央源的数量由 native/API 的能力决定；例如每玩家登记和插件逐单位伤害入口要分开计数，不能伪称所有事件都只要一个 native 注册。

示例：一个单位类型有“受到伤害”业务，就在其实例登记时建立目标角色的受伤订阅；中央伤害入口按真实受伤单位查桶。攻击者角色另查其来源桶。死亡源执行相关死亡回调，然后清理实例的活动订阅。这里的受伤、攻击和死亡必须绑定不同真实事件，不能相互代替。

## 先证明路由资格，再减少遍历

- 从原条件、动态登记及实例归属证明类型/技能资格，不根据触发器名字猜。保留条件内部的副作用与相对顺序。
- 能证明属于某类型的高频业务应实际迁入类型/实例桶；不能用“保守模式”长期保留所有全局登记而宣称优化完成。
- 对确实适用于全部单位、未知资格或尚未迁移的业务，明确保留独立全局桶/原路径及原因。其调用次序仍需与其他消费者协调。
- 登记包含原来源身份、原 trigger、事件/角色、单调顺序、调用方式和启用策略。不自动按同名或同 trigger 去重；真实重复登记行为需核实。

## 初始化与生命周期

- 枚举预放单位和接入创建/进入等入口须避免重复登记。初始化过程中产生的事件不能漏掉或人为补发；保留原 InitCustom 和 run_on_init 的相对时点。
- 变形/升级/替换时区分“同实例改变类型”和“旧实例销毁、新实例创建”。先后顺序按地图行为决定，不凭 rawcode 猜。
- 死亡不等于从地图移除；复活、尸体业务、延迟回调分别有规则。先完成应执行的死亡业务，再失效相应活动订阅；模板和必要的延迟归属仍保留。
- 无死亡移除必须有清理入口。取消 token、移除单位、销毁 trigger、销毁计时器是不同动作。
- 原生 JASS 没有一个可用于所有事件的通用注销 API。逻辑注销立即阻止业务访问；底层登记资源只有在真实 API/独占代理 trigger 允许时才回收。不能把逻辑注销报告成 native 事件已释放。
- 使用单位身份/代次和不可复用订阅 token，避免句柄复用、陈旧回调或重复清理。回调中取消/新增订阅的本轮生效规则要明确；未知原生规则的旧业务先保持原路径。

## 条件、上下文、嵌套和等待

- 原生事件、手动 TriggerExecute、手动条件执行的条件/启用语义不同，保留各自调用方式。不能统一加一个 IsTriggerEnabled 检查后宣称等价。
- 每个消费者在它原来的时点求条件、执行动作；不得先求完所有条件再跑动作。保留之前消费者及其同步嵌套副作用。
- event unit、trigger unit、攻击者、受伤单位、凶手、原消费者 trigger 等角色按实际 native/插件和事件定义取值。保存一个变量不证明 GetTriggeringTrigger/GetTriggerUnit 的隐式上下文已经切换。
- 同步嵌套分发拥有独立游标和事件 frame；内层返回恢复外层状态。一个全局数组下标或一个“当前单位”变量不够。
- Wait、计时器、局部存储和异步 continuation 分开盘点。延后执行保存其确实需要的状态与资源归属；无法保持旧上下文的项目准确列为阻断，不伪造值。
- location 等 getter 可能创建资源，不能让多个消费者共用同一个可销毁点。对 native getter 的缓存/减少调用需要逐项语义依据。
- 动态启停、回调自删、嵌套伤害、初始化创建单位及重复登记须有针对性的行为对照。不能靠禁用旧业务取得性能数字。

## 验收记录

为每个迁移项保留原对象身份、事件登记、路由资格、回调顺序、生命周期入口和未覆盖语义。每批至少记录：

| 证据 | 必须说明 |
|---|---|
| 静态盘点 | 原业务登记/新系统源/剩余登记分别多少；动态登记覆盖范围 |
| 真实接线 | 类型目录和实例入口是谁调用，多少业务已经移植，是否有新旧双执行 |
| 保存回读 | 地图、UI、工具身份；完整保存阶段结果；候选 SHA；独立重开 T 和生成脚本 |
| 游戏行为 | 原功能、启停、手动执行、顺序、嵌套、死亡/移除/复活及初始化 |
| 性能 | 同场景、相同单位规模，实际 native 登记、每事件访问/执行回调与耗时 |
| 多人 | 同步与生命周期一致性；未验就写未验 |

优化目标是让相关实例只访问相关业务。没有游戏数据时可以报告静态减少和离线通过，不能报告 FPS/延迟收益或整体性能优化完成。
