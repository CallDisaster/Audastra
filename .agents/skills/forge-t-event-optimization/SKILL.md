# 自然语言 T 事件优化

目标是减少无关业务的原生登记、条件求值和回调访问，并把实际业务迁入系统。只创建管理器、重命名触发器或把全部消费者搬到同一个循环，不算完成优化。

## 编辑入口

- 先按当前项目的 AGENTS.md 和实际工具 schema 确认地图、UI 定义、目标游戏/插件版本及保存能力。使用共用查询、编辑事务和保存服务；MCP 接入方式另见同包的 `forge-editor-mcp`，没有该 Skill 时直接发现真实工具。
- 默认新增和重构可编辑的事件/条件/动作树；保留已有自定义代码。只有作者明确指定代码实现才写作者 JASS/vJass/Lua。编译生成脚本只是保存产物。
- Agent 自测用独立副本，保留源图 SHA；正常产品保存遵循用户指定的当前图/另存为行为。

## 优化工作流

1. 分页盘点真实 T 和动态登记：事件源、角色、资格条件、原登记顺序、启停、初始化、手动执行、嵌套、等待及清理。分别统计业务原登记、系统入口和未迁移项；节点出现次数不能当活跃登记数。
2. 建立单位类型目录：每种有业务的实际类型绑定初始化 T、按事件和角色排列的业务回调，以及死亡/移除清理策略。无业务类型不制造空订阅。
3. 建立实例订阅：预放单位和运行时创建、进入、训练、出售、召唤、建造、升级、复活按真实地图语义接入同一登记链。类型模板与实例活动状态分开，登记幂等，身份防句柄复用。
4. 中央事件源按事件单位、来源、目标等真实角色查相关实例的订阅桶；必要时再按类型/技能分桶。没有资格证明的全局业务明确放入全局桶，不能猜类型过滤掉。禁止每次扫所有类型或所有业务 T。
5. 真正移植业务：保留原条件、动作和执行时点；移除已迁移的重复原登记，避免新旧入口双执行。先交一批有完整保存/回读的真实高频业务，再持续覆盖清单；通用工具缺口交给同一编辑/保存链补齐。
6. 按契约处理死亡、无死亡移除、类型变化、复活和取消订阅。死亡业务按原语义执行后才清理活动订阅；嵌套中使用失效标记和延后回收，不清作者共享哈希表。
7. 对照原图的行为和登记/回调指标，交付仍然可由作者修改的 T、命名与使用说明，以及准确的剩余清单。

实施类型目录、分发和清理前，读取 [分发与验收契约](references/dispatch-contract.md)。它规定上下文、嵌套、生命周期和证据要求。

## 交付判据

- 逐项提供“原事件登记 → 类型模板 → 实例登记入口 → 业务回调 → 清理”的映射；目录中的声明必须有真实调用者。
- 报告原登记剩余、新系统入口、已迁移业务、访问/执行回调及未迁移原因。管理 T 数量和规范命名数量不作性能收益。
- 保存后独立重开 T、回读修改，审计生成脚本中的实际登记。编译/离线回读与游戏、多人和性能分别签收，未运行的指标写未测。
- 作者未指定其他命名规则时，按“文件夹编号-自定义分类编号-分类内序号 中文功能名”组织，例如 `0-0-1 登记步兵受伤处理`；稳定对象身份不依赖名称。
