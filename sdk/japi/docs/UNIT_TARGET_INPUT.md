# 本机单位目标输入

这是内置 `audastraui` 模块 1.1.0 的可选能力，只针对已经核验的经典 1.27a 游戏映像。当前仍是内部候选，离线测试不等于原版输入、菜单、物品、Shift 队列或多人同步已经通过游戏验收。

## 请求与脚本包装

命令为 `audastraui.clickunit`，参数声明 `i`，响应为 `AJ_INT`。参数必须由本局的 JASS `GetHandleId(whichUnit)` 取得。它不是框架 token，也不是游戏地址。脚本接口为：

```jass
function AudastraUIClickUnit takes unit whichUnit returns integer
```

JASS 包装由界面库维护。应先检查请求是否成功，再解释整数结果。`AjCallInt` 失败时返回的默认零不能当作普通选择；失败要返回负的 JAPI 状态，并保留失败请求号供 `audastraui.error` / `AudastraUILastError` 查询。旧模块不认识命令时为 `AJ_UNKNOWN`，不能假装已经处理目标。

| 成功响应 | 含义 | 调用方选择行为 |
|---|---|---|
| 0 | 普通选择模式，本次未处理 | 可以执行原有选择 |
| 1 | 本次交给原版单位目标输入处理 | 不再改选择 |
| 2 | 保留给可独立确认的原版目标拒绝结果；当前适配层不产生 | 不再改选择 |
| 3 | 点目标或其他输入模式，本次未处理 | 保持当前输入和选择 |

返回 1 只表示原版处理了这次输入，不表示目标合法、技能生效、资源已消耗或多人同步已完成。固定映像中的处理入口在目标拒绝并显示原版反馈的分支也返回“已处理”；当前不能据此伪造返回 2，也不能把“仍在目标模式”解释为拒绝，因为队列操作可能保留模式。

运行库保留原版目标允许规则、错误反馈、Shift 行为、模式退出和游戏命令生成。点目标不会取该单位位置进行替代。没有另发 `IssueTargetOrder`、取消操作或自定义网络消息。

## 失败

失败使用现有协议状态。脚本返回负状态码，具体原因沿现有错误查询通道取得。

| 状态 | 原因 |
|---|---|
| `AJ_ARGUMENT` (5) | 空单位、无效句柄、非单位类型或已移除单位 |
| `AJ_UNKNOWN` (6) | 旧模块没有此命令 |
| `AJ_STATE` (8) | 游戏界面尚未创建 |
| `AJ_THREAD` (9) | 不在所属游戏线程 |
| `AJ_REENTRANT` (11) | 原版处理期间发生同步重入 |
| `AJ_UNSUPPORTED` (12) | 入口或当前模式无法核验，或原版未消费请求 |
| `AJ_STALE` (15) | 请求所属宿主会话已结束或不匹配 |
| `AJ_INTERNAL` (17) | 原版输入入口发生异常；本会话输入能力停用 |

输入异常保留异常代码、故障地址、epoch 和请求号供宿主日志记录，不扩大为绘制模块的全局停用，也不自动重试可能已经产生副作用的输入。

## 调用域、会话与资格

命令声明为 `AJ_LOCAL_COMMAND`：它由本机界面事件发起。之后可能由原版游戏生成其自身的同步命令；“本机域”不能解释为没有网络影响。不得从每位玩家都会执行的同步周期触发器广播调用此命令。

每次调用重新取得当前模式并解析单位句柄，不保存待发命令、目标对象或原版事件结构，也不在后续轮询重放。宿主核验 epoch、请求号和线程，停止时作废输入实例。原版单位句柄不具备本库框架 token 的进程范围身份保证；不得把上局保存的整数包装成新局请求来引用单位。

现有包不自动获得新能力。新 DLL 的内容身份须重新冻结，并按正常保存批准流程生成独立验收副本；同一进程不能把不同 DLL 身份混用。验收须分别覆盖普通选择、友方治疗、敌方技能、非法目标、移除单位、点目标、取消、菜单/聊天、Shift、物品、重开/换图/菜单重进。双客户端一致性另行取证，不能由单机截图或离线夹具替代。
