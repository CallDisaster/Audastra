# 地图测试的后台输入与退出

`map-test`可以向自己新启动的隐身游戏发送测试输入。它不使用`SendInput`、`mouse_event`、`keybd_event`、前台切换或真实鼠标移动。普通地图运行库不带此接收器；接收器仅由测试启动的bootstrap在`--cloaked`路径安装。

## 参数与坐标

- `--click-after <秒> <x> <y>`：左键点击；经典界面坐标范围为`0..0.8 × 0..0.6`，原点在左下。
- `--key-after <秒> <键或组合>`：例如`F10`、`Q`、`X`、`Return`、`Escape`、`Ctrl+Shift+Q`、`0x0d`。最多8键，禁止重复、鼠标键和系统/锁定键。单字符数字表示数字键；数值虚拟键码可明确写十六进制。
- 上述参数可重复，与`--screenshot-after`一起按时间稳定排序。同一时间按命令行出现顺序执行；输入完成后才执行下一项。
- `--close-after <秒>`：请求本次游戏窗口处理正常的`WM_CLOSE`，随后等待原进程自行退出。不能与`--stop`同时使用。
- `--exit-timeout <秒>`：观察期结束后等待进程树自行退出的上限，默认120秒，最大3600秒。超时返回失败、保留活动进程与测试副本，不冒充自然退出。

所有事件时间都从启动回执返回时起算，必须小于`--seconds`。最多128项事件。显式输入需要`--cloaked`；其他模式明确拒绝，没有前台后备方案。`--press-space`在首个显式输入事件开始时停止重复空格，以免干扰之后的菜单；重开后需要的空格应另用`--key-after`列出。

像素换算使用当次真实客户区：`px = round(x / 0.8 * width)`，`py = round((0.6-y) / 0.6 * height)`，边界夹到客户区内。宿主查询线程临时采用目标窗口的DPI上下文，结束后恢复；无法确认该上下文时拒绝，避免把宿主缩放后的尺寸误作游戏像素。横向按完整宽客户区拉伸；不猜测其他组件自行设置的letterbox视口。接收器再次核对客户区大小，窗口尺寸变化时拒绝本次动作。

## 所有权和输入路径

每次动作都从启动时持有的原进程句柄、创建时间、Job归属及映像路径确认唯一游戏，按PID查找它自己的接收窗口。窗口线程/PID和接收标记在发送、轮询完成时再次核对。找不到、并列窗口、编号复用、身份变化或窗口失效均拒绝。不会向桌面上其他窗口发送输入。

宿主通过固定宽度84字节的`WM_COPYDATA`包请求本方窗口子类接收器，不写游戏内存。接收器在窗口线程异步推进鼠标移动、按下、松开，或组合键按下/逆序松开；同时发布仅本进程可见的`GetCursorPos`、`GetAsyncKeyState`、`GetKeyState`和`GetKeyboardState`虚拟状态。动作使用窗口消息和进程内虚拟查询两条一致路径，不修改系统输入队列或真实键盘状态。

鼠标先悬停约100毫秒，再保持按下约250毫秒，松开后留100毫秒。组合键沿用同样的等待和保持时间。接收器只有观察到对应按下/松开消息经过窗口子类后才确认完成；虚拟状态有2秒失效保护，异常时不长期留下按住的键。窗口销毁清理定时器与虚拟状态，重建的本进程窗口重新登记。测试静音、隐身与身份门禁不因输入而取消。

经典1.27a的已知映像包含窗口消息分发、`GetCursorPos`与`GetKeyState`调用；本方界面库还直接使用`GetAsyncKeyState`。此前隐身层固定中心鼠标/零按键，单独发送按键消息不能提供界面点击所需的按住状态。静态调用点并不证明所有动态输入路径，也不代替具体游戏环境验收。

## 回执和自然退出

每项输入输出一行`test_input=<JSON>`：计划/实际时间、类型、坐标或虚拟键、PID、HWND、客户区和像素、序号、方式、完成结果，以及本进程是否观察到虚拟鼠标/键查询。启动空格的未就绪重试也有记录。`transport_complete`表示消息送达接收器并完成其输入阶段，不能当作业务回调、界面计数或菜单跳转成功；应结合随后截图和运行库日志。

`WM_CLOSE`的完成只表示正常关闭请求已排队。宿主继续等原进程树终态，记录每个原进程的`process_exit`，包括PID、是否游戏/启动器、退出码及是否确认。`unforced_process_exit=true`表示没有请求`--stop`；不单凭它认定VM清理成功。须核对游戏进程退出码和运行库的VM销毁/会话结束日志。

`--stop`仍是明确强制结束本次Job。进程非零退出、截图失败、输入失败或计划事件未执行都会使CLI失败；不能用清理成功覆盖游戏非零退出。显式输入失败立即停止后续输入；未指定`--stop`时保留活动测试，日志报告本次Job PID，便于运行者处理。退出超时也不调用强停。

## 生命周期验收范围

可用重复的`--key-after`描述菜单、确认和载入后空格，并在各阶段截图。菜单文字、语言和地图自定义快捷键可能改变路径；第一次必须先确认菜单截图，不能把固定热键序列当作场景状态识别。测试工具不会依据猜测直接调用任意游戏函数或把另启进程当成同进程换图。

重开成功后应看到新的VM会话及较大的epoch，随后相同运行库身份重新握手、界面重新创建且可点击。测试邮箱的map SHA仍是启动时冻结的产物，不能单凭它证明当前已换到哪一张图。回菜单再进、跨图、旧身份/token拒绝和自然退出都需要各自的实机证据。

`services-map-test-input-contract`只检查参数和坐标；`services-map-test-launch`保留无桌面的原创Job/退出码验证。`services-map-test-input-window`使用原创隐藏窗口验证真实跨进程送达、虚拟查询、错误身份/尺寸/序号拒绝、排除其他进程窗口及正常关闭，需要可查询的输入桌面；前置条件不满足时明确跳过。上述测试均不是游戏验收。
