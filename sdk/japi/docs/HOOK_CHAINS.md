# 已有初始化挂钩的共存边界

地图运行库可能晚于其他本机组件装入。安装前仍核对完整经典1.27a映像身份；从持有只读租约的原始文件和PE32 HIGHLOW重定位表恢复每个挂钩点的32字节运行时原码，不能把合法的绝对地址重定位当成未知补丁。

三个必需点是本地化字符串入口、初始化登记入口、主VM销毁入口。除初始化登记入口的以下特例外，窗口必须完全等于重定位后原码。数据面相关的四个窗口也要求原码；任一不满足时保留原native，不启用数据面。

初始化点可以是原码，也可以满足全部条件的已存在挂钩：

- 原码以五字节`call rel32`开头，当前恰为五字节`jmp rel32`。
- 从第六字节起的其余原码窗口逐字节相同。
- 跳转目标属于另一已载入PE32模块的可执行节，并位于已提交的可执行MEM_IMAGE页；不能是私有可执行内存或未确认映像。
- 可继续核对目标开头的直接rel32跳转，最多八跳；循环、间接跳转、短跳转、越界或不可读情况拒绝。

核验不按组件文件名、版本或某个固定目标偏移放行。测试诊断中的模块名来自实际装入的模块。

## 接链与原调用语义

本方使用DetourAttachEx修补原初始化入口，要求它报告的实际目标仍是获批入口。现有E9由Detours复制进本方trampoline；本方回调继续调用该trampoline，进入原有挂钩及其原调用路径。本方不直接跳过前任、不改前任函数正文，也不额外执行被覆盖的原call，避免重复初始化。原有挂钩自身的行为保持原样；这不证明任意外部回调都正确调用了其前任。

所有资格窗口及直接跳转节点在事务提交前再次核对。已枚举线程交给同一Detours事务后才做最后一次无分配快照检查；变化则终止整次安装。未知入口继续返回POLICY，不强行恢复或覆盖。此策略不为不协作的并发代码改写提供全局协调协议。

## 生命周期

安装成功后本方代码保持进程级固定引用，保存获批入口及已观察跳转模块的引用。调用方释放原始LoadLibrary引用不会导致这些模块在链使用期间卸载。VM reset、重开、换图、回菜单只清理会话、epoch及界面对象，不拆卸或重装进程挂钩。相同内容的后续本方副本继续复用进程拥有者；不同内容仍拒绝并要求重启。

本方不提供游戏过程中的强制热卸载。其他组件主动拆钩必须协调栈顺序，不能在后继仍依赖前任trampoline时越序释放它；模块保活不能阻止组件自行销毁内部资源。内部头部归属检查只允许当前头层移除，非头层保持原链。生产路径通过驻留避免主动越序拆钩。

## 诊断与资格

测试邮箱启用时，日志增加`hook-site site=<点名> reason=<原因>`，当前前32字节、所在模块相对位置、直接跳转目标模块位置；已观察节点另写`hook-chain-hop`。提交前变化或attach拒绝也注明点名。普通玩家路径不写这些测试文件诊断。日志不是加载成功或UI成功的替代证据。

`audastra-hook-chain`使用原创DLL实际执行原CALL、先装提供方、本方和后装提供方，核对顺序、每次原call恰好一次、前任模块引用保活、后装层退出后的还原以及完整LIFO原字节还原；同时拒绝循环、超深链、私有可执行目标、非执行目标、间接/短跳转、尾部变化和快照竞争。这是离线机器码/生命周期资格，不是游戏内VM、界面或具体外部组件签收。真实游戏仍须使用新进程验握手、截图、双方功能及完整生命周期。
