# 本机界面 Hashtable 数据面

内置 `audastraui` 模块 1.2 的可选扩展，用固定类型的原版 native 写界面属性，省去高频请求的实数格式化、转义和响应解析。控制面仍使用 JAPI v2。没有改动 JAPI C ABI，也没有改变原有 Set* 命令。

该实现已取得经典 1.27a 私有表绑定与战斗属性刷新的内部游戏证据，但尚未取得完整性能资格：同源五分钟 A/B 中，数据面组的 CPU 和私有内存增量下降，私有内存仍持续增长，点击响应和增长来源尚需分组验证。源码、夹具、成功绑定或少数错误查询不能证明性能目标与完整游戏兼容。其他游戏版本、启动器实验桥没有这项接点时，绑定返回不支持，脚本应继续走原字符串请求。

## 绑定和能力探测

第一次成功连接后，由脚本建私有 `hashtable`，只调用一次：

```jass
call AjCallVoid("audastraui.bindtable", AjArgInt(GetHandleId(privateTable)))
```

参数声明 `i`，结果 `AJ_VOID`。整数是游戏的表句柄，不是地址或框架 token。绑定会经原版 Hashtable 类型解析和弱身份检查。

| 状态 | 含义 |
|---|---|
| `AJ_OK` (0) | 表已绑定；同一有效表、同代际重复绑定成功 |
| `AJ_UNKNOWN` (6) | 旧模块没有命令，脚本可永久回退 |
| `AJ_UNSUPPORTED` (12) | 没有完整核验并安装 native 接点，脚本可永久回退 |
| `AJ_ARGUMENT` (5) | null、非表、无效表 |
| `AJ_STATE` (8) | 本会话已绑定另一张表或原绑定身份变化 |
| `AJ_THREAD` (9) | 非游戏线程 |
| `AJ_REENTRANT` (11) | 写入或绑定中重入 |
| `AJ_STALE` (15) | 会话已停止、VM 或代际失效 |
| `AJ_INTERNAL` (17) | 原版解析异常；本会话不再重试数据面 |

绑定失败用同一请求号查询 `audastraui.error`。它不改变绘制 `ready`。当前包装只在 9（线程）和 11（重入）时于下次推送重试；6、12、5、8、15、17 等状态在本局回退到字符串请求，不能反复探测，也不能把失败返回槽的默认值当作成功。

## 写入

parent key 是现有框架整数 token，child key 如下。只能在本机 UI 分支使用，不能把数据面结果写回同步游戏状态。

| child | native | 操作 |
|---|---|---|
| 1 | `SaveReal` | `SetValue(frame, value)` |
| 2 | `SaveReal` | `SetWidth(frame, value)` |
| 3 | `SaveStr` | `SetText(frame, text)` |
| 4 | `SaveStr` | `SetTexture(frame, path, false)` |
| 5 | `SaveBoolean` | `Show(frame, visible)` |

同一游戏线程立即调用原有 GameUiLibrary 操作，保持与 Set* 字符串命令的先后顺序。没有写队列、延迟重放、额外网络消息或同步层。私有表是命令通道，被消费的写入不实际存表，不承诺 Load* 读回属性；原版 `SaveStr` 的布尔结果在此表示该次属性是否成功应用。`SaveReal` 和 `SaveBoolean` 原本无返回值，错误按需查询。

值沿用旧字符串命令的边界：有限 float32；布尔值 0/1；文字是有效 UTF-8，无 C0/DEL，按 `%` 和 `;` 转义后的字节数不超过 384。空文字允许，空贴图拒绝。native 实数 ABI 是指针，字符串 ABI 是 VM object；适配器有界复制后交给同一个界面函数，不把整数猜成指针。

无效框架、已销毁或旧会话 token、属性与 native 类型不匹配、无效值、错误线程、重入、表弱身份变化和 VM 失效都不修改界面，累计诊断，不抛向脚本。若引擎界面函数异常，沿用原有绘制库故障策略；仅表解析的数据面异常停用数据面，不停用正常绘制。

没有绑定或写的是另一张表时，钩子只读原子表提示，不取得会话锁或复制消费者所有权，不读取其值、不产生数据面错误，原参数和原返回值交回原版 native。命中提示后仍完整核验线程、VM、表弱身份和框架，提示不构成授权。进程只在已核验映像、接点字节均匹配时安装三项接点；不覆盖未知改写。null VM 字符串按空文字处理；空贴图仍拒绝。

## 按需诊断和生命周期

```jass
set diagnostic = AjCallText("audastraui.dataerrors", "")
```

无参数、返回 `AJ_TEXT`，格式 `计数|最近原因`，无错 `0|`。计数到 INT32_MAX 饱和，不因查询清零。原因不含竖线，不带地图文字、表/框架数值或资源路径。写入只更新计数和枚举，查询时才生成文本；没有每次写入的 JAPI 请求/响应、JASS 字符串驻留或逐次日志。原有独立故障日志预算仍保留异常代码、入口、代际和位置。

独立地图 DLL 对实际交给 VM 的 `dataerrors` 响应另留最多 32 行诊断，只含代际、请求号、状态和经格式核验的计数。它既不受普通 2048 行预算影响，也不占用异常的 64 行预算；不记录原因文字或写入值。该日志只证明查询时的累计计数，不能把少数查询扩大为逐写日志或尚未发生的错误。

停止模块、销毁主 VM、换图或重开前清绑定，随后才销毁界面消费者。新 VM 创建新数据面实例和错误计数，必须重新绑定；框架 token 在进程内不复用。旧事件或旧 token 不能被新表绑定恢复。

验收需要分别记录：普通表转发、绑定/错误负例、旧 token、原生目标输入，以及同图同操作的字符串 A / 数据面 B 各五分钟 CPU、私有内存和点击响应。若字符串表增长未直接测量，必须标明未测，不能从内存曲线推导精确字符串数量。

属性写入的数据面不会自动改变事件监听。当前脚本事件轮询仍走带请求身份的字符串控制面；即使没有属性变化也可能继续调用。内存归因需区分数值写入、文字生成、事件轮询以及原版游戏自身的分配，不能把数据面组的剩余增长直接称为某个组件泄漏，也不能用关闭输入监听的诊断图代替可交互产品验收。
