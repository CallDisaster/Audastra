# 数值文字与整数事件数据面（运行库 1.3）

这些是运行库命令及私有表槽的契约。客户端必须先连接模块、绑定私有表，再协商对应命令。旧客户端可以继续使用普通文字和字符串事件命令；不能同时用两种事件通道消费同一队列。JASS 封装和生成器需与所选运行库包配套更新。

创建文字框后，通过 `audastraui.textformat` 注册格式，参数类型为 `ds`（框架句柄与文字）；返回 AJ_VOID，状态为 AJ_OK 才表示注册成功。格式支持 `{0}`…`{7}`、`{i:0}`…`{i:6}`、`{{`、`}}`。省略精度时实数最多三位小数、去尾零及小数点；整数精确显示完整 int32。固定精度保留相应位数，零位没有 `.0`，所有精度的负零规范成正零。半值向远离零方向舍入。

实数按游戏实际传入的 binary32 处理。编辑器若从十进制作者值重新转换，不一定得到游戏实际收到的位值；格式比较须先确保输入相同。`Text::FormatUiReal(float, precision)` 与 `FormatUiInteger(int32_t, precision)` 提供共用格式算法。实测的同一输入样例：123.125/2 → 123.13，2.675/2 → 2.67，-0.0001/3 → 0.000，默认 → 0。整数 2147483647 不经过实数转换。

绑定表的 parent 为 frame，child 约定如下：

| Native | child | 作用 |
|---|---:|---|
| SaveReal | 16…23 | 更新实参 0…7，类型为 real |
| SaveInteger | 24…31 | 更新相同逻辑实参 0…7，类型为精确 integer |
| SaveBoolean(true) | 6 | 一次提交格式化后的完整文字 |

数值更新本身不写框架；一次刷新可以更新多个变化的实参，最后提交一次。重新注册格式会清空实参。缺少模板所需参数、非有限实数、非法占位、无效 UTF-8、控制字符、旧句柄或编码后超过 384 字节的结果均拒绝，保留此前文字，不截断。最多保存 1024 个存活格式槽；框架退役、停止模块或 VM 重建后释放。显式提交会实际写入，不因之前的格式缓存而吞掉普通 SetText 之后的刷新。

没有格式数据面时，客户端应缓存模板和带类型实参，在提交时拼接 JASS 回退。回退的 R2SW 零位结果须去掉 `.0`，各精度负零须规范化；Push 阶段不拼字符串。失败不能永久缓存成“以后都不能连接”。可选扩展须通过不会停用整个界面模块的原始能力探测协商；旧运行库不认识 textformat 或 eventtable 时，只回退对应功能，不把基础界面连接记成失败。

高频事件轮询也可以绕开字符串请求。先调用低频命令 `audastraui.eventtable`（无参数、AJ_VOID）协商。成功后使用私有表保留的 parent 0：

1. 每 tick 先 `FlushChildHashtable(table, 0)`，然后 `SaveBoolean(table, 0, 7, true)`。运行库泵一次实际输入，并取队列首项。
2. `LoadInteger(table, 0, 0)` 为 1 时，child 1 是 frame，child 2 是事件 kind。先派发此项。
3. 取下一项前再次清理 parent 0，再 `SaveBoolean(table, 0, 8, true)`；此操作不重复泵输入。每 tick 最多处理 32 项，剩余队列留待下一 tick。

完成标记最后写 1；空队列或写入失败保持 0。事件总队列有界，过滤已退役 token，整数与旧字符串传输共享同一 FIFO，不复制两份。只有协商失败才回退旧传输。保留旧的 50Hz 字符串 poll 会继续产生递增请求字符串，单独替换文字格式槽不能消除该路径的内存增长。

文字参数、提交内容、输入结果和鼠标查询诊断仅在专用测试邮箱启用时写出，并有数量上限；正式玩家路径不启用这些观察通道。静态夹具、同值格式对照与完整游戏生命周期、性能出口是独立验收项目。

普通文字和贴图槽支持 VM 的空字符串表示，包括零引用以及可读的中间描述中为空的字符缓冲；未连接或不可读的引用仍拒绝。空文字清除旧文字，空贴图路径交给已核验的原生贴图接口清除原资源，不能把未填充图标槽记录为参数错误。无效 UTF-8、控制字符与编码长度预算继续检查。
