# 打开与保存耗时测量

启动参数只在启动时解析；计时开关发布后供工作线程只读访问，进程内编译选择保存在本窗口选项中。无效的隔离配置名称以`SETTINGS_PROFILE_INVALID`写入标准错误。

诊断模式另外输出`editor_timing_thread=微秒|ui或worker|事件`，对应同一个阶段边界。打开快照细分为来源散列、目录、成员解码和最终来源复核；绑定、保存准备和提交也有各自子阶段。嵌套阶段不可直接相加。

界面线程使用20毫秒精确定时器；每次`open-total`或`save-total`结束输出`editor_ui_responsiveness=微秒|operation=阶段|max_gap_us=间隔|timer_us=20000`。记录包括尚未投递的最后一段阻塞，反映该操作中定时器最久未得到响应的间隔，不把操作总耗时或工作线程CPU耗时当作界面卡顿。诊断关闭时不创建该定时器。

编辑器支持以下显式测量参数。没有这些参数时，设置位置、界面和保存流程保持原样。

- `--settings-profile measurement`：使用独立的设置、助手配置和凭据目录。配置名限1–48个英文字母、数字、下划线或连字符，首字符为字母或数字。窗口仍显示Audastra；不会复制、迁移或删除默认配置。适合在同一Windows用户下启动专用测量实例。
- `--diagnostic-timings`：向标准错误写入`editor_timing_event=微秒|事件`。时间使用本进程的单调时钟；记录打开快照、工作区、提取、物编转换、来源复核、绑定、刷新，以及保存准备、工作线程、服务内部阶段、额外回读和提交。服务阶段以`save-timing.begin/`与`save-timing.end/`配对，其余阶段以`begin/`与`end/`配对。
- `--in-process-only`：本实例的地图保存显式使用进程内脚本后端，不回退到外部编译程序。普通启动仍使用所配置的工具链。

例如，以独立配置打开一份自己的地图副本：

```text
war3-map-editor.exe --settings-profile measurement --diagnostic-timings --in-process-only --open-map sample.w3x
```

需要采集输出时，由启动程序重定向标准错误。配置和权限应在该专用实例中设置；MCP调用仍遵守实际工具schema、当前工程身份和修订检查。

计时仅增加诊断输出，不跳过编译、来源检查、成员预算、写后回读或提交检查。嵌套阶段的耗时包含子阶段，不能重复相加。打开地图的计时不包含应用启动前的等待；启动耗时应由启动程序另外记录。

响应式打开与正常界面保存会把自持有的纯输入交给工作线程。打开只传入路径和不可变的游戏目录、字符串快照；保存先冻结归档、地形、触发器、函数目录及覆盖字节，后台不借用工程的可变文档。准备结束与提交前仍分别核对修订，晚到编辑会使保存结果不能标记为当前编辑已保存。保存忙状态覆盖准备、工作线程和提交，期间不能再次保存、切换工程或关闭窗口。

有效物编目录可在绑定前基于实际打开或回读通过的归档准备；装回时核对归档实例、完整SHA、路径、字符串与游戏根。存在战役、待导入表覆盖或身份不符时使用原来的完整捕获服务；来源验证器仍执行，显式强制刷新也重新捕获。同步探针保留同步调度，不能用其线程分布代替正常窗口的响应测量。

工作线程与界面线程的阶段可以交错。分析器应按线程分别配对边界；界面根阶段的墙钟时间包含等待工作线程，不等于连续占用界面线程的时间。最终判断卡顿仍使用心跳最大间隔。

CLI的`map-edit-save --save-timings`使用同一保存服务阶段，但不包含编辑器界面绑定和提交阶段。比较两种入口时应固定源文件、函数库和工具链、修改请求、输出方式及机器负载，并比较真实候选内容。

活动编辑器的`editor_save_map`可显式传`rebuild_terrain_shadow: true`，在正常保存时重算阴影；默认关闭。这个选项不能用于内部验收副本用途，保存资格和拒绝诊断仍由原服务决定。
