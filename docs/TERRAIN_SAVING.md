# 地形保存

世界页面中的修改进入同一撤销历史，可以保存到工程，也可以通过“保存地图”或“另存为”写入地图。编辑器、命令行和 Agent 使用同一套地图保存检查。

普通保存保留原来的静态阴影。需要重算时使用文件菜单“计算阴影并保存”；它读取当前地图的最终地形、对象和本机游戏光方向，写出并回读 `war3map.shd`。当前支持普通地面，以及使用实际静态 MDX 悬崖模型的异层悬崖接收面；悬崖接收面按原始几何组、变体和地形起伏计算。标准装饰物的静态模型投影目前仍限普通地面，投影模型须无动画控制器、无倾斜、正缩放、摆放高度与实际地面一致。坡道、特殊地形模型、MDL 接收面、动态模型、相关物编覆盖或尚未支持的组合会明确拒绝这次计算，当前编辑仍保留，可以继续普通保存。重算失败不会用空阴影替换旧文件。

命令行可在 `map-edit-save` 的地图、来源 SHA、W3E SHA、工具目录、游戏目录和候选路径之后加 `--rebuild-shadows`，可单独计算，也可随地形笔划一起计算。MCP 对应 `save_terrain_shadow_candidate`，参数为 `source_map_path`、`output_path`、`expected_source_sha256`、`expected_terrain_sha256`；工具和游戏来源由宿主配置，写到新候选路径。这些入口使用同一个计算和保存服务，不接受客户端提供的阴影字节或“已验证”标记。

当前支持：

- 干地高度和荒芜修改。
- 地面贴图和变体调整，包括替换贴图槽位、追加已知贴图，以及通行属性不同的地面材质。
- 已有水面的高度调整、浅水和深水笔刷新建水面。
- 普通悬崖笔刷升降层级、更新材质和周围地形；保存含已有干地、湿地坡道的地图，以及一级干地直坡、九点外角坡道的创建与移除。
- 替换已有悬崖贴图槽，保留槽数量及全部顶点和变体字节；保存会核对每个改变槽的实际旧、新资源行，包括未使用的槽。悬崖表追加、删除和新重复编号仍会拒绝。
- 边界笔刷设置、清除地形边界，以及专用可玩区域命令调整范围；保持地图尺寸和对象坐标不变。
- 通行笔刷增加不可走、不可飞、不可建限制，以及撤回本工程此前画下并保存的限制。
- 与地形同次保存单位属性和无关资源导入；会改变静态通行依赖的物编、资源仍须分开处理。
- 经典无皮肤格式中的单位、建筑和物品摆放与地形共同保存；具体操作和组合限制见下文。

这些操作均受下述实际资源、对象和格式范围限制。能证明通行不变时保留原通行文件的字节；通行有变化时先完整解释原文件，再重建新结果。荒芜修改只同步对应位，通行笔刷仅修改本工程声明的限制。保存前会再次检查实际资源和最终成员，保存后独立回读确认。

地形修改可以和地图名称、作者、说明、建议人数一起保存。此时设置必须是完整且可精确往返的经典 W3I v25，除这四个说明字段和下述专用可玩区域命令外须保持原字不变；玩家和环境等其它设置仍请分开保存。修改说明与地形的顺序不影响最终保存检查。

世界页的“可玩区域”先读取当前范围，再按西、南、东、北四条地格边界调整；东边与北边不包含在范围内。镜头边距从当前游戏资源读取并显示，不能用界面默认值代替。这项操作保持地图尺寸、世界坐标和对象位置不变，统一修改地图边界遮罩、可玩区域、相机设置和通行；保存时使用最终范围重新生成游戏相机初始化、小地图与图标。范围太小、超出地图、来源变化或旧通行无法完整解释时拒绝操作。撤销、重做及工程保存恢复保留同一个复合命令；扩大或裁剪地图尺寸暂不支持。

命令行的正常 `map-edit-save` 可追加 `--terrain-bounds west south east north`，与其它地形操作按参数顺序执行。MCP 的正常地图保存可在 `terrain_strokes` 中使用 `{"kind":"playable_bounds","west":1,"south":1,"east":9,"north":7}`；四项须为整数，不接受点数组、客户端规则或搬动对象选项。编辑器内的 `edit_terrain_bounds` 使用当前会话绑定，可先 `dry_run` 预览；独立目录补丁不重建游戏脚本，因此不会将这项修改伪装为已完成地图保存。

“边界”笔刷设置或清除地形边界，保留原地图外缘；可玩区域通过上面的专用范围命令调整。CLI 使用 `--stroke boundary circle 32 32 0 true` 设置边界，末尾改为 `false` 清除；支持 circle、square 和 0..16 半径。MCP 保存使用 `kind:"boundary"`，并明确填写 `shape`、`point_space`、`radius`、`value`、`points` 和 `follow_doodads:false`；`value` 只能是 JSON 布尔值。

小地图随正常保存自动重建；遇到生成器暂不支持的内容时会保留原小地图并提示原因。作者导入的 BLP/TGA 小地图会保留。阴影保留上次计算的结果。

正常保存也会重建矿点、商店和开始位置的小地图图标。图标使用最终的单位与能力数据、实际可玩区域，以及本机游戏资源中的玩家颜色；它与小地图底图分别处理，保留作者底图时仍可更新图标。图标生成能力或预算不足时保留原图标并警告，来源变化、修订过期或输出冲突仍拒绝保存。

改变地面通行属性、跨越水深阈值和改变普通悬崖阻断轮廓时，保存会尝试按实际地形和资源重建通行。先用相同规则重算原图，逐格核对原通行文件，只有所有差异均可解释时才写入新结果；本工程已保存和当前画下的限制分别保留。保存后继续撤销或重做地形，再保存时也会重新计算。

本轮重建只支持经典格式、已核实的世界范围，以及地形和对象通行贡献均可完整解释的地图。对象层接受实际数据明确证明不贡献静态通行的可破坏物，以及占地可完整解释的普通装饰物。普通装饰物可以是标准对象、原对象覆盖，或从标准对象直接派生的一层自定义对象；部分特殊地形模型及符合条件的既有可行走桥梁也可保留，具体限制见下文。单位存在本身不会被当作拒绝理由。未知字段、不能解释的外部通行修改、尚未核实的坐标布局和缺失资源会明确报错，原图不被覆盖。

已有坡道的地图也可参与上述通行重建，包括远处含水和坡道自身含水的静态地图快照。保存分别按源地形和候选地形的完整邻域及实际 `Terrain.MaxHeight` 计算高端、低端坡道种类、四角阻断和有效地高；水深与严格覆水采用同一地高及实际水面规则，不把所有坡道位视为可通行。配置缺失、冲突、来源变化或超过支持层级范围时会拒绝保存；不会使用默认高度上限。原通行文件仍要完整核对，普通装饰物和符合条件的特殊模型继续按各自规则叠加，保存后的撤销、重做也走同一重建和回读检查。此处支持的是静态保存重建，不包含运行时活动地形形变，也不改变坡道工具和水刷工具各自的编辑范围。

普通悬崖的层级笔刷共用已捕获的实际地形规则、正常会话和保存计划，允许处理已有干/湿坡道。水深下限、岸线、荒芜与高度衰减读取同一当前快照的完整 R/S 有效地高；后处理只清除不再属于有效坡道地格的旧坡道位，不创建新坡道。地物跟随使用实际最大层级及完整第二圈分类，保持相对地高，并与地形共用一次撤销重做。未知邻域或不足的事务预算会拒绝整笔。新普通悬崖记录使用带规则摘要和水限制选项的 FTJ2；旧无摘要悬崖记录仍按旧算法恢复。

浅水和深水笔刷也可以从已有干/湿坡道落笔。新水算法v2在起点分别固定原始地高B与实际最大层级规则下的完整地高G：扩大平台仍使用B，无原水时水面取G，有原水时保留原水面并用G推导目标层级；后续采样点共用这一固定锚点。原版顺序仍为扩大平台、普通悬崖、清除失效旧坡道位，再执行特殊模型、水、荒芜与高度衰减。完整坡道查询、对象跟随和锚点复核均预收有界工作量，邻域含未知字段、来源漂移或预算不足时拒绝整笔。Core候选私有的锚点验证结果仅对同一会话、来源、修订和before快照有效。

世界页面的“拐角坡道”可创建或移除一级外角的九顶点坡道，包括形态符合条件的含水外角。每次点击处理一个拐角，光标吸附到所在半格的中心；普通尺寸、强度和贴图选项不会混入这笔操作。实际规则读取、完整邻域检查和候选计算放在后台，提交时仍核对当前地图修订；失败不留下半笔修改。含水创建保留原水面和原始地高，不删除摆放；启用高度跟随时仍保持对象与地面的相对高度。被水覆盖的荒芜按实际坡道地高清除。多级台阶、其它坡道相交或补角范围超出九点的形态会明确拒绝。

其它复杂新坡道创建仍未扩展。未持有实际最大层级的兼容显示/拾取路径仍使用既有直坡近似；完整 R/S 编辑与通行重建不构成复杂坡道模型和显示验收，亦不包含活动地形形变。

地图有普通装饰物摆放时，保存会从同一实际来源读取可破坏物表、装饰物表和字段元数据，并检查 `war3map.w3b` / `war3map.w3d` 的实际内容或缺失身份。即使没有自定义可破坏物，也要排除装饰物同名造成的类别冲突。非可行走值支持标准对象、原版覆盖，以及直接继承标准对象、且父对象没有原生覆盖的一层自定义对象；不从显示文字或缺省值推断。重复字段、损坏表、同名对象类别冲突、复杂继承和未知元数据仍拒绝。字段地址必须与实际表中的逻辑值一致，不会删除字面引号或空白后猜测字段。保存期间修改或导入这些依赖也会拒绝，应先单独保存物编与资源，再编辑地形。来源完整且类型可确认后，仍须通过原通行文件的逐格比较，不能因对象属性为零而跳过；缺少实际表或超过解析预算时会明确报错。

既有可行走桥梁支持唯一标准可破坏物、经典v2 W3B原对象覆盖，以及直接继承唯一标准父的一层自定义对象；自定义对象的父不能有任何W3B或W3D记录。有效 `walkable` 须明确为1，`pathTex` 须明确非空且未禁用，`fixedRot` 须为有限的[-360,360]数值。原生记录为空时逐字段沿用标准值；非空记录只接受实际 `DestructableMetaData` 唯一绑定的 `walkable`、`pathTex` 和 `fixedRot` 覆盖，逻辑表须为 `DestructableData`、`index` 须明确为0，wire类型须与元数据精确一致。此元数据使用可破坏物的平面标量规则，不要求装饰物的 `repeat` 列；如显式声明重复、data或其它索引则只接受0。自定义桥实际用于分类的 `walkable` 及实际覆盖字段不能带非空 `useSpecific` / `notSpecific` 对象选择器；无关或未用字段的选择器不因此导致整表拒绝。

`walkable` 覆盖须为Int32的0或1，0继续走既有零贡献域；`pathTex` 须为String，明确空串、`_` 或小写 `none` 不回退标准非空值，仍超出本桥域；`fixedRot` 须为实际Real/Unreal F32，显式零或负值均覆盖标准值。其它覆盖字段、同名装饰物、父有原生覆盖和多层自定义继承仍拒绝。地图可以保留其它对象的W3B记录。每个桥实例必须保持wire `flags=2`、`lifePercent=100`，并使用同一资源来源的24/32位真彩TGA（type 2未压缩或type 10 RLE）和已经支持的吸附、旋转、裁边及预算规则；RLE解包计入同次捕获预算，完整格式限制见[占地贴图格式](TERRAIN_FOOTPRINT_FORMATS.md)。原版从缺失的装饰物类别字段回退到DOO摆放rawcode的第二个字符；自定义桥使用新ID，不能改用父ID。该字符为大写 `C` 时，与普通装饰物共用下述实际启动类别目录：有C记录采用4格、已知无C采用2格、来源未知则拒绝；其余字符采用2格。因此父ID的第二字符即使为 `C`，也不改变非 `C` 新ID的网格规则。可破坏物表自身的 `category` 不能替代这个回退规则。桥仍只按RGB非零像素抑制对应格terrain贡献，不输出普通RGB阻挡位；该网格接通不扩大实例状态、DOO冻结或游戏运动的证据范围。

桥占地中RGB任一通道非零的像素会抑制对应格的地形通行贡献，包括地面、水、边界、悬崖和特殊地形模型的投影；alpha不决定该抑制，RGB全黑不抑制。重叠普通装饰物的静态阻挡和本工程声明的通行限制继续叠加。“需要通行重建且含支持的存活桥”路径会逐字冻结桥记录的所有字段、嵌套掉落物及桥之间的相对顺序；桥本身的Z、XY、朝向、增删和顺序不能混改。无关普通对象可以修改、增删或重排，保存分别完整重建修改前后的静态占地，再冻结最终完整DOO并独立回读。特殊尾段可以随本会话可信浅水/深水笔刷删除，并沿正常保存、另存、工程恢复和保存后的撤销重做继续核对私有事务来源；普通摆放编辑或外部DOO字节不能取得该授权。仅接受完整解析到EOF的经典格式和版本0特殊尾，未知附加区仍拒绝。原版特殊模型删除链不改普通桥的投影来源；这不扩大桥的摆放高度跟随范围。既有通行不变、仅摆放高度变化的保存检查保持原合同。桥面高度、模型碰撞、桥上/桥下和重叠桥的实际运动仍须由同一输出地图在原版与游戏中独立验收。

普通装饰物要求生效的标准 `Doodads.slk` 行明确提供 `pathTex`。空字符串、`_` 或小写 `none` 表示没有占地；非空路径按下述贴图规则读取。已有经典 v2 `war3map.w3d` 原对象或自定义对象覆盖时，保存会按实际装饰物元数据读取字段：明确空值清除标准占地，非空值使用覆盖后的贴图，未修改该字段才沿用标准值。覆盖只接受类型明确、没有变体或索引歧义的字段；未知字段、重复地址和可能的字段别名会拒绝。所需元数据按需从地图或配置的游戏资源读取，并参与同一预算、来源核对和最终回读。

自定义装饰物只接受直接继承唯一标准装饰物、且父对象没有地图原生覆盖的一层继承；不能与标准对象或可破坏物同名。缺少标准字段、未知占位值、路径文件读不到或对象类别冲突，都不能当作“没有占地”。符合条件的普通装饰物可与支持的可破坏物混合摆放；地形修改仍走相同的原通行逐格检查、保存与回读。多层自定义继承、战役继承和带变体的原生覆盖尚未接入。

普通装饰物按实际生效的 `category` 首字节选择类别，不trim、不lower、不解释后缀。无类别覆盖时沿用标准对象或标准父；经典 v2 W3D 的原对象或上述一层自定义对象也可覆盖类别，字段ID由同次实际元数据中唯一的 `DoodadData.category` 绑定确定。覆盖要求实际String类型与wire一致（包括实际 `doodadCategory` 元数据类型）、明确 `repeat=0/index=0`、其余索引为零且没有对象选择器；未知字段、重复或可能的地址别名继续拒绝。缺格、显式空串或任意前导 `_` 均按 `war3map.doo` 摆放ID的第二字节回退；自定义对象使用新ID，不借父ID，显式空串不借标准类别。有效首字节仅接受33至126的可打印ASCII；只有大写 `C` 请求下述实际启动目录选择，其他字节使用2格。标准类别的 `WESTRING_` 文本需要额外本地化来源，本单元保守拒绝；原生String覆盖直接取值。本次只扩大已证普通类别读取域，不代表原版保存或游戏验收。

普通装饰物支持实际首选 TGA 为均匀正方形占地图的情况，例如常见的同色 2×2、4×4 占地图。要求贴图为未压缩24/32位、边长1至256、全部像素（包括alpha）相同。摆放XY按实际生效类别的原版网格吸附；坐标靠近吸附边界、浮点舍入可能产生不同结果时会明确拒绝。保存从实际地图或游戏来源读取贴图，按原版吸附、通道属性和所有实例的叠加重建通行；贴图字节和生效来源在保存前后都要一致。完整旧通行校验、原有限制、预算和撤销重做继续生效，不把缺失或未知占地当成零。

普通有效 `C` 类由实际启动类别目录选择原版2格或4格吸附，类别可来自上述标准字段、原生覆盖或新ID回退。编辑器以配置的游戏目录作为fresh startup的exeDir语义，按1.27a expansion内部规则重建第一次profile重载以前复制的目录；不要求用户提供固定SHA的原版EXE或Storm.dll，也不声称掌握任意已经运行的原版进程历史。固定56项初始化profile按原序全部加载，每项先查exeDir下basename loose文件，再查完整相对路径，最后按共用五包目录从高到低查找。地图、tileset和Melee/Custom前缀视图不参与这个启动目录。路径必须能按当前ACP无best-fit/默认替换地往返，并符合原版ANSI MAX_PATH字节容量；链接、重解析点、大小写别名冲突、实际ANSI路径probe与目录身份不一致及无法读取的来源均拒绝，不能作为已知缺失。所有来源已知时，目录实际枚举key的首字节存在大写 `C` 才选择4格；已知没有大写C记录才选择2格。key不必恰为单字母C，`Custom`也可产生C记录。按原版文本语义保留第一次有效key拼写，大小写不敏感的后定义只追加值：`c=x` 后 `C=y` 仍为小写，`c=` 不创建key，`C=""` 或 `C=,` 可以创建。真实来源未知时不会回退为2格。保存前和独立回读重建并核对完整56项winner、SHA/长度、五包入口present/absent及canonical根身份；相同最终C结果或相同内容移到更高来源也不能绕过CAS。loose和核心MPQ通过同一deny-write HANDLE有界读取，启动MPQ不扫描prefix、不读取未使用的listfile，实际头表读取与解析工作计入共享捕获预算。既有完整旧WPM校验、保存/另存及保存后撤销重做继续生效。

普通装饰物（包括实际启动目录已经选择网格的 `C` 类）也支持矩形或不同像素的 TGA 占地图，宽高分别为1至256。要求实际生效的 `fixedRot` 可解释：没有原生覆盖时读取标准对象字段，有覆盖时按同次捕获的唯一实际元数据读取经典 v2 W3D 的 Real/Unreal F32，wire类型必须完全一致，且元数据须明确为非重复、零索引的 `DoodadData.fixedRot`。本轮仅接受有限的[-360,360]度；显式零与负值不会回退标准值。负值保留原摆放角，非负值应用固定旋转；编辑器始终按原版先用摆放角吸附坐标、后应用固定旋转的顺序处理四个方向，逐像素合成通行，并处理地图边缘裁剪与多个实例重叠。该覆盖可用于原对象或上述一层自定义继承，不扩大父原生覆盖或复杂继承范围；类别仍按上述独立合同读取。顶部和底部原点、24/32位像素共用相同规则；透明像素的RGB通行属性仍然生效。临界角度或坐标不能唯一确定时会指出原因，保留原图和未保存修改。普通对象现在也可读取 type 10 真彩 RLE，占地解包计入同次捕获预算；特殊地形模型和旧同色接口仍只接受未压缩格式，完整支持范围见[占地贴图格式](TERRAIN_FOOTPRINT_FORMATS.md)。普通对象已支持首选TGA确实缺失时的有界BLP1回退；右侧原点仍未接入。

已有特殊地形模型使用独立的规则。保存从实际 `war3map.doo` 特殊段读取地格位置，按实际装饰物表和原生覆盖取得占地贴图；支持零变体、宽高为4的倍数且不超过256的完整TGA。通道值为255才阻挡，重叠时使用先登记的模型；边界、水深和不可通行水规则继续生效。贴图alpha的层级形状必须与原图及修改后的悬崖顶点都一致，并满足实际配置中的高度上限。普通贴图、悬崖或已有水位编辑仍须保持该形状；修改破坏形状时会指出原因并保留草稿。新建浅水/深水笔刷可以删除形状被本笔破坏的特殊模型：按原版阶段先收集坐标，再依当前顺序查找同坐标首项，以末项覆盖删除位置。重复坐标不会合并，剩余顺序影响重叠通行。普通装饰物及特殊段的其它字段保持原样，不重塑特殊模型。实际特殊段含空占地记录且本笔需要删除时，本批明确拒绝，避免猜测未进入原版运行时列表的记录应如何保存。

浅水和深水笔刷可以新建水面，并按当前地图实际加载的地形规则调整岸边和悬崖。每笔固定起点与随机种子，预览和提交使用同一个算法；一笔的地形、荒芜通行位、特殊模型删除和对象高度变化可以一起撤销。提交前会核对实际资源，资源发生变化时需重新落笔。通行重建仍须满足上述条件；保存分别使用旧/新完整特殊模型集合重算贡献，并逐格解释全部旧WPM。未支持的对象或无法解释的旧通行仍会拒绝。

水面工具中的“移除水面”仅清除水面标志，保留地形高度、原始水高度、悬崖、坡道及所有摆放。它支持形状和尺寸、撤销重做及工程恢复；最后一片水移除后，正式保存仍须核对原有水规则并完整重建旧/新通行性，保留作者原有通行限制。命令行使用 `--remove-water square 32 32 1`（形状、顶点x、顶点y、半径0..16）；MCP保存使用 `kind:"remove_water"` 和普通的形状、坐标、半径字段，会话笔刷使用 `brush:{"kind":"remove_water","shape":"square","size":1}`。不填写水高、悬崖槽位或随机种子。

地图可以保留自己的 `war3mapMisc.txt`，其中的 Terrain、Water 等游戏配置不会替换水刷、坡道和特殊地形模型保存所用的编辑器启动规则，也不会仅因文件存在而阻止这些操作。该文件按普通地图成员保留；实际启动配置和通行资源仍须通过原有来源、内容、冻结输出与回读核对。

已有 FTJ1/FTJ2/FTJ3 笔划记录继续使用原来的规则摘要格式；摘要中的历史地图 Misc 常量槽仅用于兼容，不表示当前文件缺失，也不参与实际资源验证。旧记录的水算法版本、完整来源基线和原通行逐格核对仍按原合同处理。

新图尚未选择悬崖材质的平地也可以画水并保存，保存后仍可撤销、重做，再保存相应结果。此类材质转换只接受完整平地邻域，附近有坡道、地图边界、未知地形字段或未解释的悬崖时会拒绝。有效材质仍须来自当前实际资源，原有通行限制也继续逐格核对。

浅水/深水导致的特殊模型删除只能由可信水刷事务产生；正常保存和另存会冻结该私有状态，保存后仍可撤销、重做并再次保存。外部DOO覆盖或普通摆放编辑不能提供此授权。`.forge`可以保存当前真实地图保存基线之后、完整且可表达的前向地形笔划前缀。重新打开时，服务从实际来源建立独立会话，按原顺序重放全部笔划，成功后才整体安装真实命令及撤销回执；这仅恢复该前缀，不是恢复保存以前的全部历史。独立目录MCP事务继续共用同一个owned replay工厂。

前向记录保存笔刷选项、完整采样点、随机种子、水位限制和对象跟随选项，不保存可授予来源的锚点。每笔从实际before地形和第一点重新捕获锚点；水刷重新读取实际资源，并比较其内容、地图/游戏winner及已证缺失项摘要。正式恢复还逐项核对来源SHA、完整W3E/WPM、DOO、Units、其余公共成员及缺失身份，并核对最终全部成员覆盖、删除清单和通行层P/已保存S/当前S。摘要或相同最终DOO字节本身均不能建立私有删除谱系。游戏资源目录只来自宿主配置，不接受工程提供外部读取路径，也不把资源字节作为工程中的授权载荷。

水算法版本独立于规则摘要。FTJ1/FTJ2中的所有水笔划固定恢复为旧v1，继续拒绝实际访问区内的旧坡道，且再次编码逐字保留旧格式；FTJ2只表示原版普通悬崖选项。包含至少一笔v2水的前缀才使用FTJ3，其每笔水明确记录v1或v2，并保留FTJ2的普通悬崖字段。未知算法、截断字段，以及没有任何v2水却使用FTJ3的非规范记录都拒绝恢复；新默认值不会升级旧记录。UI、Services、MCP、CLI和工程恢复共用同一typed水路径与结构算法，完整后处理没有第二份实现。

世界页替换已有地面或悬崖贴图槽、追加地面贴图槽时，会在后台读取实际地图与游戏资源、核对完整原表和当前对象来源，再提交同一可撤销命令。此类命令用独立的 FTJ6 变体随 `.forge` 保存，不伪造笔刷采样点；因此“追加或替换贴图槽 → 水刷删除特殊地形模型 → 再替换悬崖槽”的完整前缀也能按原顺序恢复。当前表格、资源赢家或旧槽值变化时拒绝该前缀，不能只恢复水刷之前或之后的一部分。地图保存仍另外核对原通行与全部派生文件，记录本身不授予保存资格。

FTJ6 的已有槽替换继续使用原算法；地面表末尾追加使用独立算法，绑定追加前的完整表及实际资源来源。地面表最多16项，重复材质、跳槽、重排、删除和悬崖表追加不在此恢复范围内；不改变旧 FTJ1～FTJ5 的字节格式。贴图命令计入每前缀128条命令上限，普通笔刷仍共用4096个采样点上限。重复填入同一槽的现有值不产生命令。低层调用未提供实际资源owner时仍只保存完整raw工程草稿，不会自动生成FTJ6或取得可信来源。

每次真实地图保存后，下一份记录从新的保存基线开始。撤销到保存边界以前、分叉替换已保存前缀、混合不可表达命令，或超出记录预算时，工程仍完整保留raw成员覆盖、删除清单和通行分层；不截断、拆分笔划，也不裁剪原撤销历史。通常会持久保存“草稿保留，水刷来源未恢复”的警告，重开和后续工程保存继续展示。资源缺失、依赖变化或重放预算不足也采用此raw回退，不能安装半个前缀。旧版无记录工程仍按raw方式打开，不从其覆盖推断私有水刷来源，正式地图保存仍会拒绝未证实的DOO修改。

记录版本、codec、声明与载荷对应关系、基线身份或完整最终输出不符时拒绝打开，当前工程保持。实际地图基线无法锁定、读取或验证时也拒绝打开；读取容量不足仍可回退raw，但降级前继续复核实际来源未变，不能把地图损坏当成水刷资源缺失。工程保存准备只冻结有界笔划与无历史的只读基线；完整来源读取和身份补齐在工作线程进行。恢复的最终比较逐字段读取现成数据，预收raw候选驻留和比较工作，不再复制两套完整覆盖与APR。CAS仅记录有界typed笔划和规则摘要；来源与限制层继续由既有独立scope覆盖。按现有修订服务合同，这些scope参与地图和工程两个保存目标的比较，因此相同最终地图字节但不同可撤销前缀仍会保守显示修改状态。

前向记录限制为128笔、累计4096个采样点；原UI单笔仍允许65536点。记录wire上限64MiB，原精确来源成员读取仍受64MiB存储/解码总帽约束；资源owner累计128MiB、工作64M、候选及撤销512MiB的重放预算不变。工程容器总帽仍为512MiB，完整baseline、raw草稿和导入优先，只有剩余容量足够才附加记录。极限情况下raw与旧manifest已恰好占满512MiB，新增警告字段也无法容纳时，仅返回可见警告，不新增该字段、不删旧内容、不扩大容量；即使重开时没有警告字段，raw也不会取得私有水刷授权。正常有空间的回退会持久保留警告。

地形升降时，随地面调整高度的单位和普通装饰物可以一起保存。此类高度跟随会逐字核对高度以外的字段，并保留特殊装饰物段。经典无皮肤 Units 文件可以完整读取并逐字往返、原通行也能完整解释时，单位、建筑和物品的移动、旋转、缩放、复制、新建和删除也可与地形共同保存。单位的动态占地不烘焙进静态通行；脚本和地图标记使用最终完整摆放。

上述单位摆放组合不包含开始位置（`sloc`）的联动设置。普通非桥装饰物的移动、旋转、缩放、新建、复制和删除也可与地形同存，保存会分别重建修改前后的静态占地。普通对象修改可以与浅水、深水笔刷造成的特殊模型删除共同保存；`.forge` 工程按原操作顺序恢复这两类修改，恢复后仍可撤销、重做和正常保存。特殊记录须分别匹配已保存和当前的私有事务状态，外部直接修改尾段仍会拒绝。含桥时可以修改其它普通对象，桥记录本身及相对顺序须保持不变。CLI 当前可通过 `--rotate` 或 `--copy-source` / `--copy-offset` 把纯 Units 旋转或复制与地形共同提交；此组合不能同时启用地物高度跟随，也不能再混入说明字段、物编或触发器事务。MCP 独立目录的地形与摆放事务仍分别导出，正常地形保存工具不接受额外的摆放参数。

地形仍可与单位生命值等物编字段、无关导入文件共同保存：保存先完整核对原通行，再冻结本次物编与导入的确切输出。改变静态通行所依赖的可破坏物、装饰物或资源时仍需分开处理。CLI 的字段批次与地形共同提交时，只接受地图名称、作者、说明和建议人数；MCP 的地形与字段批次仍分开提交。可玩区域使用上述专用命令。资源缺失、来源改变或无法确认属性时仍会拒绝写回。

通行笔刷会单独记录本工程画下的限制。即使原地图在同一位置已经禁止通行，这次笔划也能撤销、重做并随工程保存；擦除只撤回本工程的限制，不删除来源地图已有的限制。普通保存和另存会写出这些修改，保存后仍可撤销或擦除自己的限制。

继续编辑时请同时保存 `.forge` 工程，它会记录原有限制与本工程已保存限制的归属。重新打开工程后可以继续擦除本工程的限制；只重新打开裸地图时，编辑器无法知道哪些位由本工程画下，会保护地图里的所有既有限制。旧工程只恢复当时实际记录的限制，不推测遗漏的重叠笔划。

通行限制可以与上面支持的高度、水面、悬崖、坡道、贴图、荒芜、边界、专用可玩区域及受支持的单位摆放修改一同保存；地形须通过通行不变或原图逐格重算检查。超出上述格式与组合范围的修改仍需分开保存。通行笔刷不能直接清除原有地形或对象阻断。

命令行的 `map-edit-save` 可以使用 `--stroke texture circle 32 32 0 Lgrs` 更换地面贴图，或使用 `--stroke water-height circle 32 32 0 170` 调整已有水面基础高度；其余地图路径、来源 SHA 和工具来源参数仍按命令帮助填写。MCP 的 `save_map_edit_candidate` 使用 `kind:"texture"` 与 `ground_texture`，或 `kind:"water_height"` 与 `water_height`；所有入口都会执行相同的通行检查。

一级干地直坡使用 `--stroke ramp circle 32 32 0 true` 创建、`--stroke ramp circle 32 32 0 false` 移除。坐标是台阶所在的顶点索引；半径固定为0，三点形态及完整干地直台阶邻域由共用坡道规划器检查，不使用高度或强度参数。MCP 对应 `kind:"ramp"`、`shape:"circle"`、`radius:0`、`set_ramp:true` 或 `false`，并明确提供 `point_space`、`points` 和 `follow_doodads:false`；布尔值不能写成字符串或数字。附近有水、边界、地高不齐、拐角、多级悬崖或不完整旧坡道时仍会拒绝。已有湿坡道参与通行保存的能力不扩大这个编辑范围。

新建水面使用独立的命令参数：`--water-stroke shallow circle 32 32 1 0 42 true`。依次填写浅水/深水（`shallow`/`deep`）、形状、起点顶点坐标、尺寸（1..8）、已有悬崖贴图槽位（0..14）、随机种子（uint32）以及是否限制水位（`true`/`false`）。相同输入和种子可以重放得到相同笔划。

拐角坡道使用 `--corner-ramp <世界x> <世界y> true` 创建、末尾 `false` 移除。MCP保存对应 `kind:"corner_ramp"`、`point_space:"world"`、单点 `points`、`set_ramp:true/false` 和 `follow_doodads:false`；不传 `shape`、`size`、`radius` 或高度参数。会话工具的 `brush` 仅传 `kind:"corner_ramp"` 与 `value:true/false`。CLI/MCP不自动吸附：两轴坐标都须为地形offset加128的整数倍再加32或96，实际外角、规则和完整邻域由同一服务核对。工程恢复保留原笔划顺序、规则身份及当时的算法；旧干地记录不会自动扩大为含水编辑。

MCP 的 `save_map_edit_candidate` 对应 `kind:"shallow_water"` 或 `kind:"deep_water"`，显式填写 `shape`、`point_space`、`size`、`cliff_texture`、`seed`、`enforce_water_limits`、`points` 与 `follow_doodads:false`。起点基准和地形规则由保存服务从实际地图取得，不接受调用方提供。`water_height` 仍只用于已有水面高度调整。

`edit_terrain_stroke` 在当前编辑器会话及独立目录事务中使用相同水刷选项。例如 `brush:{"kind":"shallow_water","shape":"circle","size":1,"cliff_texture":0,"seed":42,"enforce_water_limits":true}`；`points` 是世界坐标，仍须精确回传最新 `terrain_binding`、工程身份和修订，并明确 `dry_run`。浅/深水的六个选项必须全部填写；不能混入普通笔刷参数、起点基准或最终DOO字节。预览不取得事务或修改撤销栈，编辑器内提交沿原撤销栈；独立目录提交须先 `begin_edit`，经 `preview_edit`、`validate_edit` 后才能导出，`rollback` 放弃活动事务。独立事务暂不混入物编、资源、触发器、预放或其它地图字段。

同一地形序列最多128笔、累计4096点。普通笔刷和每笔水刷共用有界重放；累计资源捕获/保留上限128MiB、工作量上限64M、候选与撤销预留上限512MiB，每笔仍受原资源和水刷算法预算约束。资源计量包含解码输入和规则解析工作预留，独立核对保留容量；它不是MPQ存储字节的最小成功读取量，每次存储读取仍受原有上限约束。普通笔刷按固定扫描阶段、实际采样足迹分别预收，临时候选峰值与累计历史分开计量；悬崖层级传播按整笔实际队列、邻域和逐采样刷新访问累计，默认硬上限16M，重放只可用序列剩余额度收紧。实际资源缺失、来源或资源变化、累计预算超限时不返回部分候选。独立MCP的游戏资源来自进程配置 `FORGE_MCP_WAR3_ROOT`；请求不能指定另一个游戏目录。导出地图候选会重新核对实际归档与目录来源，并保留每笔种类、顺序、种子、水位限制选项及对象跟随选项。

以上保存与编辑器内回读检查不代表已通过原版编辑器或游戏验收。涉及旧版 YDWE、memory_hack 或自定义资源的地图，请使用副本在原版编辑器重新打开，并在游戏中核对通行、外观及触发器行为。
