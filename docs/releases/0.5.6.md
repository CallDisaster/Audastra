# Audastra 0.5.6

补丁版：修复用 KKWE 作为运行库时地图测试启动不了的问题。

## 地图测试

- 原样的 KKWE（plugin/warcraft3 里没有 config.cfg）测试时报“lua53.dll 缺失”。现在和 KKWE 自己测试时一样，装入 plugin/warcraft3 里的全部插件，只跳过 config.cfg 里设为 0 的；没有 config.cfg 时全部装入。插件先全部装入，再逐个初始化。
- 运行库目录里混放了不同版本的 YDWE、KKWE 文件时（例如 KKWE 的 bin 里放进了 YDWE 的 ydbase.dll、lua53.dll、ydwar3.dll），以前进游戏后才报“runtime-load-library，Win32=127”。现在启动前就停下，写明哪个插件缺哪个文件里的几个函数。把目录换回一套完整的 KKWE 或 YDWE 即可。
- 群文件“外部依赖”里的 YDWE 文件要放进 Audastra 的外部依赖目录，不要复制进 KKWE 目录，否则会覆盖 KKWE 自己的 ydbase.dll，KKWE 本身也会用不了。
- 手写 Lua 入口和 YDWE 一样可以不加引号：`call Cheat("exec-lua:init")`。KKWE 自带的 Lua 演示图可以测试了。
- 错误报告里，同时有 lua53.dll 和 luacore.dll 的目录会标成“YDWE 与 KKWE 文件混放”。

## 升级

- 0.3.0 及以后的版本可以在编辑器里“检查更新”直接升级。
- 0.2.0 及更早版本请从发布页手动下载便携包，原因见 0.3.0 说明。

## 已知限制

- 界面编辑器里游戏自带的原版样式还没在游戏里逐个核对，暂不在创建卡片里列出。背景、图标、容器上的点击和移入移出事件，以及改父控件、阵列后在游戏里的位置，也还在核对。
- 删除物体时，按变量或函数取值的触发器参数、地图导入的脚本无法静态检查，需要你自己确认没有用到。
- 少数模型预览仍显示不出来，原因见 0.5.2 说明。
