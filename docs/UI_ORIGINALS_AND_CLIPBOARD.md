# 原版界面调整与自己的界面复制

原版界面的调整保存在地图的 `AudastraUI/<界面编号>.json` 中。选择原版节点后，属性栏列出本版本实际支持的显示、位置、缩放和透明度；未通过游戏验收的属性显示“不支持”，生成触发器时也会拒绝。原版节点的功能保持由游戏处理。

支持表以经典 1.27a 的 JASS 地图验收为依据；其他脚本宿主组合需要独立核对加载与界面行为。

| 原版部件 | 显示/隐藏 | 移动 | 缩放 | 透明度 |
| --- | --- | --- | --- | --- |
| `resourcebarframe` | 支持 | 支持 | 需显式位置 | 支持 |
| `upperbuttonbarframe` | 支持 | 支持 | 需显式位置 | 支持 |
| `Minimap` | 支持 | 支持 | 不支持 | 不支持 |
| `MinimapButton1..5` | 支持 | 支持 | 需显式位置 | 支持 |
| `Portrait` | 支持 | 支持 | 需显式位置 | 支持 |
| `CommandBar` | 支持 | 支持 | 需显式位置 | 支持 |
| `InventoryButton1..6` | 支持 | 支持 | 需显式位置 | 支持 |
| `HeroBar` | 支持 | 支持 | 需显式位置 | 支持 |
| `InfoBar` | 支持 | 支持 | 需显式位置 | 支持 |
| `TimeOfDay` | 支持 | 不支持 | 不支持 | 不支持 |
| `consoleui`、`ChatMessage` | 不支持 | 不支持 | 不支持 | 不支持 |

未列部件不自动获得支持。控制台包含独立渲染部件，整组调整没有通过完整布局核对；应分别调整已支持的部件。消息框的布局调整在运行库调用前拒绝。`InfoBar` 的原生物品面板拥有六个物品按钮，其移动、缩放、隐藏和透明度也会影响这些按钮；画布会反映这一父变换。

“隐藏”“恢复原样”、属性修改和拖动使用地图现有的导入修改事务，可以撤销、重做、正常保存。恢复原样会删除该节点的调整记录；它恢复的是描述和下一次生成结果，不向正在进行的游戏发送热更新。修改后应重新生成触发器并重新测试地图。

有 FDF 模板的原版节点可以右键“复制为自己的界面”，新界面使用同一个模板。由游戏代码直接创建且没有模板的节点不能这样复制，菜单会说明原因。复制模板不会复制游戏为原版对象安装的功能。

## 描述格式

`origins` 可省略，旧描述无需升级。名字使用原版节点表的规范标识。位置始终相对屏幕：`point` 是自身锚点，`toPoint` 是屏幕锚点，省略 `toPoint` 时与 `point` 相同；`x`、`y` 是偏移。屏幕逻辑尺寸为 0.8 × 0.6，左下为原点。

```json
{
  "format": "audastra.ui",
  "version": 1,
  "id": "Layout",
  "origins": [
    {"name": "resourcebarframe", "visible": false},
    {"name": "Minimap", "position": {"point": "TOPRIGHT", "x": -0.01, "y": -0.02}},
    {"name": "Portrait", "position": {"point": "BOTTOMLEFT", "toPoint": "BOTTOMLEFT", "x": 0.2075, "y": 0.030625}, "scale": 1.2}
  ]
}
```

缩放范围为 0.1–4，透明度为 0–255，位置偏移绝对值不超过 2。一个节点不能重复声明；没有任何属性的空调整应使用删除操作。读取拒绝未知字段、未知名字及不合法数值，写出采用规范格式。

原版默认锚点的偏移也可能随缩放改变。因此可用的缩放要求同时写显式位置。界面属性操作会把当前画布中心一起保存为位置，作为同一次撤销操作；Agent 直接写描述时需提供位置。生成器会检查这一条件。此条件不表示小地图的实际渲染视口支持缩放。

## 生成与运行

生成结果包含普通自然 T 的“原版界面调整”触发器。它每 0.2 秒等待界面库就绪，最多等待 30 秒；定位先于缩放，随后设置透明度和显示。可以在触发器编辑器里阅读和修改动作。未安装运行库、找不到节点或节点类型不符时记录错误并返回，地图继续运行。

运行库按稳定名字查找当前会话的原版对象，检查固定字段、对象类型、物品栏边界及布局尺寸。它不销毁这些游戏拥有的对象。成功的调整由游戏线程的 0.1 秒计时器重新应用，覆盖单位切换、英雄切换、菜单和窗口变化引发的重排；新会话会清空旧对象和重放记录。该接口不修改原版按钮的业务功能。

相关界面库函数为 `AudastraUIOriginalFrame`、`AudastraUISetOriginalVisible`、`AudastraUISetOriginalPosition`、`AudastraUISetOriginalScale`、`AudastraUISetOriginalAlpha`。诊断通过现有 `AudastraUILastError()` 获取。直接调用低层函数不会绕过对象校验，也不等于该操作已经进入编辑器的支持范围。

## 自己的界面复制粘贴

在节点树或画布上选中自己的框架，使用 Ctrl+C/Ctrl+V，或右键“复制”“粘贴”。粘贴到选中的描述根或父框架，包含全部子框架以及需要的数值、状态覆盖和事件声明，可以跨描述粘贴。

冲突编号依次加 `_copy`、`_copy2`，内部锚点、数值绑定、文字/贴图/模型模板、状态覆盖和事件里的框架引用同步更新。原描述保持不变。事件声明的新编号会产生新的事件键；地图中另写的业务触发器不会作为剪贴板内容自动复制，需要为新键登记所需行为。

复制范围外的框架锚点会明确拒绝，避免跨描述后断引用；可以先改用父框架或屏幕锚点。剪贴板受同一描述格式、大小和操作预算约束，不接受原版调整记录或模拟计时器。

MCP `game_ui_description_edit` 使用同一编辑服务：

- `set_origin`：`{"op":"set_origin","origin":{"name":"Minimap","position":{"point":"TOPRIGHT","x":-0.01,"y":-0.02}}}`。
- `remove_origin`：`{"op":"remove_origin","name":"Minimap"}`。
- `paste_frame`：`{"op":"paste_frame","clipboard":<一个框架子树的完整 audastra.ui 描述>,"parent":<可选父编号>,"index":<可选插入位置>}`。

查询原版节点时，`original` 字段返回各属性能力、原因，以及 `scale_requires_position`。保存和生成仍需使用当前工程修订身份，不能凭能力查询自动批准原生运行库。
