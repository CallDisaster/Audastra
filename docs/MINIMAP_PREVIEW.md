# 查看小地图

世界页默认显示“当前编辑”，也可切到“已保存”。当前视图复用经典保存的生成器、取色、后处理和内容噪点种子，包含未保存的地形和文档修改；默认图层为地形、水、装饰物/可破坏物及可玩区裁剪（0x8B）。当前图先编码再解码，与实际保存图的像素语义一致。查看不写BLP/MMP、不增加撤销项或修订。停笔500ms后开始后台生成；后台只消费冻结文档，来源或修订变化时丢弃结果。

荒芜使用实际地形集纹理整图均色；区域按已核的25%混色显示。通行配色证据尚未补全，选择时明确报告不可用，不以猜测颜色替代。单位、起始位置和图标可选择点状叠加，不声称与原版图标绘制相同。尚未保存的导入资源覆盖或物编修改、目录工程或不支持的资料形态会拒绝当前生成，详情进入错误列表。

当前图上点击或拖动可平移世界相机，黑边不接受点击。白框为实际完成帧四角在相机目标高度平面的投影；无可核定完成帧或射线不相交时不画。它不是逐点计算的地形遮挡边界。相机移动不改地图镜头对象或文档修订。

世界页左侧的“已保存小地图”显示当前打开地图归档中的实际 `war3mapMap.blp`。这是底图，不含独立图标、单位或区域覆盖，也不代表当前未保存地形已经重新生成。没有底图时明确显示缺失；来源待核验、内容损坏或超出预算时清除旧画面并显示原因，不使用上张地图或默认图片替代。

修改地形后会提示地图有未保存修改，撤销、重做继续使用原来的地图事务。查看和刷新本身不增加撤销记录、不改变地图修订、不写地图。正常保存后，面板跟随新的地图基线更新；如果保存服务保留了旧底图，看到的仍是实际保留的内容。“保存成功”不等于“小地图已重新生成”。

面板在前台只复制已打开快照中的底图字节，后台拥有并解码这些字节，不重新占用源地图读取句柄。完成时重新核对来源路径、SHA、会话代次和来源变更状态；切图后的旧结果不能覆盖新地图。包含匿名成员且打开快照没有列出底图时，显示缺失状态未确定；可通过下面的精确归档查询确认。目录工程的面板不冒充已保存地图归档预览。

CLI：

```text
war3-map-cli minimap-preview sample.w3x <完整小写源SHA-256>
war3-map-cli minimap-preview sample.w3x <完整小写源SHA-256> preview.ppm
war3-map-cli minimap-preview sample.w3x <完整小写源SHA-256> current.ppm --source current --game-root <游戏目录> --layers 0x8b
```

默认输出JSON元数据，包括存在状态、成员SHA、解码RGBA SHA、宽高和只读标志。可选PPM路径必须尚不存在；导出的是新查看副本，RGB以黑色合成透明通道，原RGBA及地图不变。输出冲突、缺失底图或写入失败会报错，不覆盖已有文件。

活动编辑器和独立MCP均提供`query_minimap_preview`，接受绝对`source_path`、`expected_source_sha256`、`source=current|saved`（兼容默认saved），以及默认关闭的`include_rgba`。current可选`layers`整数位、`units/starts/icons`布尔值。独立入口current按指定文件生成，可传`game_root`，文档修订为0；活动工程current须带`project_identity/expected_revision`，路径及SHA须匹配工程，游戏目录使用宿主设置，返回当前文档修订，后台未完成时`pending=true`，可稍后查询。保存或写命令执行中会拒绝查询。saved不接受图层或游戏目录参数，不读取未保存覆盖或切换工程。

默认只返回元数据；显式请求像素时返回`rgba8_top_down`，响应最多2MiB，活动日志不复制像素正文。客户端应按图像处理，勿把传输数据打印成日志或写入说明文档。

三个入口共用同一个BLP解码和像素身份服务。单底图输入上限4MiB、边长上限512、解码工作量上限64MiB；没有为了预览静默缩小原图。归档来源打开与精确捕获仍保留其各自的校验和预算。无可读listfile时，CLI/MCP仍按固定底图名精确查询；缺失、空文件、格式损坏与读取失败分别处理。该只读结果不授予保存资格，也不构成原版编辑器或游戏验收。
