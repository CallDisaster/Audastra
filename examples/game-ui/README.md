# 界面示例

这里是用 Audastra 界面描述做的六个完整示例，每个目录有：

- `<编号>.json`：界面描述（框架、数值、状态、事件）。
- `triggers.txt`：驱动这份界面的触发器，自然 T 功能写法。

示例只用游戏自带的贴图和原版、YDWE 函数，可以照着改，也可以整套装进自己的地图。

## 装进地图

1. 导入描述：在导入管理里把 `<编号>.json` 导入为 `AudastraUI\<编号>.json`，界面工作区就会出现这份描述。
2. 生成界面触发器：在界面工作区选中这份描述，点“生成触发器”。需要先启用 AudastraUI 函数库。
3. 写入示例触发器：让助手用 `edit_trigger_graph` 的 `apply_feature_text` 把 `triggers.txt` 写进一个类别，或者照着在触发器编辑器里写。除伤害统计外都需要 YDWE 函数库。
4. 改“登记”触发器：把里面的技能、单位类型、图标换成自己地图的。

触发器名末尾的英文部分（如 `Cast_Register`）不要删，它让脚本里的触发器名不重复。

## castbar 读条条

- 按施法事件给每个施法者记一份读条，读条或引导完成（阶段 1）、引导每跳（阶段 2）、打断（阶段 3，含施法者死亡）时运行登记的效果触发器。
- “读条 登记 Cast_Register”每个技能一组：技能、读条秒数、引导秒数、跳间隔（0 为不跳）、效果触发器。秒数要和物编的施法时间、持续时间一致。示例登记了两个效果触发器“效果 读条 Bolt”“效果 引导 Ritual”，要自己建。
- 效果触发器里用“获取逆天局部变量”取：施法单位、目标单位、目标X、目标Y、技能、等级、阶段、跳数。
- 读条能否移动、什么算打断由物编和游戏决定，示例只计时和运行效果触发器。界面只显示本机玩家自己的读条。

## party 团队框架

- 5 格，每格名字、血条与“当前/最大”生命、蓝条、死亡与过远标记、头像、4 个增减益图标。
- 开局和之后进入地图的玩家英雄自动加入。自己加入或移出：把单位设给 AUP_Member，再运行“团队 加入 Party_Join”或“团队 移出 Party_Leave”。
- 每 0.1 秒刷新。点格子：举着单位目标技能时把技能放到这个队员身上，否则选中他。
- “团队 登记 Party_Register”按顺序列要显示的增减益，“团队 头像 Party_Portrait”列要显示头像的单位类型。

## target 目标框架

- 显示本机玩家选中的单位：生命、法力及其数字、名字、等级、死亡、头像、6 个增减益。取消选择时清掉。
- 点框架：举着单位目标技能时把技能放到目标身上，否则选中目标。
- 增减益与头像的登记同团队框架。

## meter 伤害统计

- 按玩家统计对敌人造成的伤害，召唤物的伤害算主人的。每 0.5 秒从高到低刷新 8 行：玩家名、伤害、每秒伤害、占第一名的比例条、占全部的百分比，标题右侧是秒数。
- 首领战开始时运行“伤害 清零 Damage_Reset”。原版没有治疗事件，不统计治疗。

## actionbar 技能栏

- 两行共 12 格，显示本机玩家选中单位的技能：图标、热键、剩余冷却与秒数、法力不足。
- “技能栏 登记 Bar_Register”每项写单位类型、第几格、技能、图标与热键；热键要和物编一致。单位没学会的技能不显示。
- 点格子：选中的就是当前单位时按下这一格的热键，否则先选中它。

## talents 天赋树

- 技能栏上方一个入口按钮，打开 5 层 × 3 列的天赋面板；所有英雄共用面板，每个英雄登记自己的天赋表。
- 英雄到达某层的解锁等级就开放这一层，每层选一次、选定不可改，选择结果同步给所有玩家。
- “天赋 登记 Talent_Register”每个天赋写层、列、名字、说明、学会的技能。开局为每个玩家建几个看不见的同步单位，点天赋时靠选择这些单位同步。
